## 1. 产品方向

v1 解决「真题怎么考」；v2 解决「备考怎么管」：

| 能力 | 一句话 | 载体 |
|---|---|---|
| AI 成绩分析 | 基于历史成绩做能力曲线、分数曲线、薄弱真题定位 | 仪表盘（重做） |
| 备考计划 | 作战计划 + 倒计时 + 自动打卡 + 心得 + AI 昨日总结 | 备考计划页（新增） |
| 备考学习 | 背单词（机械化三模式起步） | 学习中心（推翻重做） |

使用动线：**打开应用 → 仪表盘看数据 → 计划页看今天该干什么 → 机考/背词执行 → 数据回流仪表盘**。

## 3. 页面设计

### 3.1 仪表盘 · 成绩分析

三段式布局：

**① 能力总览 4 卡**：当前水平（最近一场总分+四科）· 趋势 vs 上次（±band）· 目标差距（读计划表，无计划时显示「未设定」）· 累计模考（场次/本周/用时）。

**② 分数曲线**（recharts LineChart）：

- **切换维度：总分 / 听力 / 阅读 / 写作**（口语无真题数据，不出维度）
- 数据点口径（P6.1 修订）：**总分 = 仅 COMPLETED 完整套卷场次**；**单科 = 场次内成绩 + 单科散考交卷一并统计**（实线实心点 = 场次，虚线空心点 = 散考）
- 雷达口径：各科最近成绩 vs 该科全部交卷均值（含散考）
- 目标分虚线叠加（总分切换时显示总目标线；分科目时显示该科目标线）
- 悬停 tooltip：该场四科 band + 「查看成绩单」链接（`/session/<sessionId>`）
- 无数据时显示空态引导（「先去完成一场模考」→ 机考模拟）

**③ 四科能力雷达**（recharts RadarChart，复用写作批改卡同款）：最近一场 vs 历史均值双系列；无数据维度自动隐藏。

**④ 薄弱真题清单**（巩固练习闭环）：

- 粒度 = 卷 × 科目（paper 级），非单题
- 判定：该卷该科**最近一次 band < 目标分 − 0.5** → 列入；无目标分时用 6.0 兜底
- 排序：离目标差距降序；展示「最近 band / 已做次数 / 目标」
- 「再练一次」按钮直达 `/exam/<examId>`；重做达标自动移出清单
- 口语无真题，不参与

### 3.2 备考计划页

**状态 A · 未开启 → 三步向导**：

1. **考试日期**：考前须知弹窗（§4.2）确认后，弹出**单一日历组件**直选年月日（机考每日可考，不再分「形式→年→月→日」多级筛选）
2. **目标分数**：总分 + 四科（可只填总分，四科留空用总分−0.5 兜底）
3. **每日任务量（可选）**：背词数/天（听力/阅读/写作/口语量化后续版本加）

生成逻辑：剩余天数 × 目标差距 × 当前水平 → LLM 产出分阶段作战方案
（基础期/强化期/冲刺期，每阶段给出周任务模板）→ 用户确认后落库。
LLM 不可用时降级为规则模板生成（按天数三等分）。

**状态 B · 作战主页（三栏）**：

| 左栏 | 中栏 | 右栏 |
|---|---|---|
| 倒计时大数字（天 + 日期）+ **考前须知提醒按钮**（ⓘ，悬停/点击显示 §4.2 同一份须知文案，与向导弹窗复用同一组件） | 今日任务清单（来自计划模板，完成态自动勾选） | 打卡日历（月视图） |
| 目标达成进度条（当前 vs 目标） | 打卡规则说明 | 备考心得（写入/查看） |
| 「调整计划」入口 | 学习情况切换：每日/每周/每月 | AI 昨日总结卡片 |

**自由调整**：改考试日期/目标/每日量 → 只重算未来阶段，**不重置已完成打卡与历史**。
换新计划（如考完再战）：旧计划 ARCHIVE，活动与日记保留关联。

**打卡规则**（自动，无需手动点）：

- 当日**交卷 ≥1 次**（任何科目）→ 打卡 ✓
- 当日**背单词 ≥5 个** → 打卡 ✓
- 两者都满足 → 满卡（日历深绿）；仅一项 → 浅绿
- 数据源：study_activities 当日行

**AI 昨日总结**：次日启动程序时（仪表盘首次加载检测 `last_summary_date < 昨天`）触发；
输入 = 昨日活动数据 + 昨日心得；输出 = 总结 + 今日建议，写入昨日日记的 `ai_summary_json`。
LLM 未配置/失败时静默跳过，下次启动重试。只在首页提示一次。

### 3.3 学习中心 · 背单词

> 表结构暂不设计（等实施时定），本节只定交互。

- **词库选择**：内置雅思核心词 + CSV 导入（`word,meaning` 每行）
- **三种模式**（机械化背诵，先简单）：
  1. 英→中快刷：看英文四选一
  2. 听音辨词：Web Speech API 播放发音 → 拼写
  3. 中→英拼写：看中文（+音标提示）→ 打字拼英文
- 词进度字段预留 box_level（为 SM-2 记忆曲线留钩子，第一版只记「背过/没背过」）
- 背词数实时写 study_activities（≥5 触发打卡）
- 费曼学习法 / 记忆曲线复习 / 听力精听 / 阅读精读：虚线占位卡，点击 toast「二期开放」

## 4. 考试日期调研与考前须知

### 4.1 调研结论（2026-09 查证）

| 形式 | 规律 | 来源可靠性 |
|---|---|---|
| 纸笔考试 | 历史上全部落在周六；每月约 2–4 场 | 官方（chinaielts.org） |
| 机考 | **几乎每日可考**（除法定假日/系统维护），多数城市一天多场；考前 3 个工作日截止报名 | 官方 |
| 现状 | **2026 年 9 月起中国大陆全面取消纸笔，仅机考**（UKVI 纸笔更早停止） | 第三方（新航道），以官方公布为准 |

**设计决策**：既然以后只有机考且每天都能考，**直接用一个标准的年月日日历组件**选日期，
过去日期禁用（可选日期必须晚于当天），不再需要「形式→年→月→日」多级筛选，
也无需硬编码任何场次数据。

### 4.2 考前须知弹窗（复用组件）

触发场景（两处，共用同一文案与组件）：

1. **向导选考试日期前**：进入 STEP 1 时先弹出须知，用户点「我知道了，去选日期」继续
2. **作战主页倒计时旁**：提醒按钮（ⓘ 图标），点击显示同一份须知（收起式卡片或小弹窗）

须知文案（Markdown 常量，便于维护）：

```text
考前须知
├─ 换题季说明：每年 1 月、5 月、9 月为雅思口语换题季，新题在该月首场考试启用。
│  若想降低口语碰新题的风险，建议避开换题季首场；本应用写作/听读不受影响。
├─ 费用说明：普通雅思与 UKVI 报名费统一 1990 元（以官方最新公布为准）。
├─ 官方报名：请前往教育部教育考试院雅思报名官网 ielts.neea.cn 报名与查询考位。
├─ 考位建议：机考虽每日可考，但热门城市周末考位紧张，
│  建议提前 1–2 个月关注考位释放情况并尽早报名（机考考前 3 个工作日截止）。
└─ 出分时间：机考考后 1–5 天出分，最快 48 小时。
```

（成本/出分等数字以官方最新公布为准，文案集中在常量里，改一处两处生效。）

## 5. 数据表设计（3 张新表）

> 沿用 v3.1 设计原则：snake_case 物理列 / JSON 列合并同类信息 / 不为未来过度设计。
> 全部走 Drizzle migration；背单词表实施前另出设计。

### 5.1 study_plans — 备考计划（1 行 = 一份作战计划）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer PK | |
| exam_date | text | 考试日期 `YYYY-MM-DD` |
| target_overall_band | real | 目标总分（Overall Band Score，0–9、0.5 步进），如 6.5 |
| target_scores_json | text(JSON) | 四科目标 `{listening, reading, writing, speaking}`，缺省项用总分−0.5 兜底（读取时算，不存兜底值） |
| daily_goals_json | text(JSON) | 每日任务量 `{words: 30}`，键随版本扩展（听读写量化后续加在这里） |
| phases_json | text(JSON) | 计划内容本体：向导确认时由 LLM/规则生成的分阶段作战方案（基础/强化/冲刺期 + 各阶段周任务模板），形状见 §5.4。作战主页「今日任务清单」「阶段进度」按它渲染；「调整计划」重算未来阶段后回写此字段 |
| status | text | `ACTIVE` / `ARCHIVED`；同一时刻仅一条 ACTIVE |
| created_at | timestamp | |
| updated_at | timestamp | 调整计划时刷新 |

### 5.2 study_activities — 备考活动（1 行 = 一天的活动汇总）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer PK | |
| activity_date | text | 统计日 `YYYY-MM-DD`，**unique** |
| exam_set_submission_count | integer | 完整套卷（连考）交卷数（对应 exam_sets 表） |
| listening_submission_count | integer | 听力单科交卷数 |
| reading_submission_count | integer | 阅读单科交卷数 |
| writing_submission_count | integer | 写作单科交卷数 |
| speaking_submission_count | integer | 口语交卷数（预留，当前无口语真题恒 0） |
| memorized_word_count | integer | 背单词数（当日背过的词累计） |
| created_at | timestamp | |
| updated_at | timestamp | |

写入时机（upsert `activity_date` 键）：

- 交卷 API 成功后：对应科目 `*_submission_count` +1；完整场次 finalize 时另将 `exam_set_submission_count` +1
- 背词模块每完成一词：`memorized_word_count` +1

打卡判定（查询时计算，不物化）：`exam_set/listening/reading/writing 的 submission 任一 > 0` 或
`memorized_word_count ≥ 5` → 当日打卡；两者都满足 → 满卡。

> 统计字段后续扩展（精听时长、口语练习等）直接加列到本表，不出新表。

### 5.3 study_journals — 备考日记（1 行 = 一篇心得）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | integer PK | |
| journal_date | text | 心得所属日 `YYYY-MM-DD` |
| period | text | `daily` / `weekly` / `monthly` |
| content | text | 自己写的心得，任何时候可写可改 |
| ai_summary_json | text(JSON) | 可空，AI 昨日总结，形状见 §5.4 |
| created_at | timestamp | |
| updated_at | timestamp | |

约束：**unique(journal_date, period)** — 每天一篇日心得、每周一篇周心得、每月一篇月心得（upsert 语义）。

### 5.4 JSON 形状规范

```jsonc
// study_plans.phases_json
[
  {
    "name": "基础期",
    "weeks": [1, 2, 3],
    "focus": "词汇打底 + 听力精听",
    "weeklyTasks": [
      { "type": "words",    "label": "背单词 30 个/天" },
      { "type": "listening","label": "听力单科 2 套/周" }
    ]
  }
]

// study_journals.ai_summary_json
{
  "summary": "昨日听力填空 6 错 4，集中在 Section 1 数字与拼写…",
  "suggestions": ["背词侧重数字类词汇", "重做 Jan 2025 听力巩固"],
  "basedOn": { "submissions": 1, "words": 32, "journalExcerpt": true },
  "model": "MiniMax-M3",
  "generatedAt": "2026-09-02T09:01:00+08:00"
}
```

## 6. 数据流

```text
交卷(API) ──┬─→ study_activities upsert(对应 *_submission_count +1; 连考完成 exam_set_submission_count +1)
            └─→ (既有) exam_records / exam_sessions
背词(模块) ──→ study_activities upsert(memorized_word_count+1)
心得(表单) ──→ study_journals upsert(journal_date+period)
启动检测   ──→ AI 昨日总结: 读昨日 activities + journal → LLM → 回写 journal.ai_summary_json
仪表盘     ──→ 读 exam_sessions(曲线/雷达) + exam_records(薄弱清单) + study_plans(目标线)
计划页     ──→ 读 study_plans + study_activities(日历/统计) + study_journals(心得/AI总结)
```
