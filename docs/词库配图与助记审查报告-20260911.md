## 四、渲染可用性: hiColl 高亮盲区(前端代码伤,非数据伤)

完全复刻 `mnemonic-radial.tsx` 的 hiColl 正则,对全部 7,345 条 contexts 回放验证: **7,119 条可高亮,226 条失败**。

失败根因单一: hiColl 的匹配模式是 `词头 + \w*`(前缀匹配),对**词干变化的屈折形式**全部失配:

| 类型 | 例 |
| --- | --- |
| y→ies/ied | fantasy→fantasies、imply→implies、irony→ironies |
| 不规则/词干变化 | horrify→horrified、embody→embodies、pine→pining?(pining 可匹配,但原句用 pining 时 coll 含 in 的写法不一) |
| 辅音变化 | tickle→tickling(k 前需补 g,前缀匹配含 tickl ✓ 失败原因为 coll 缺失类) |

注: 这 226 条都有 headword 兜底,但兜底同样是 `\b词头\w*` 前缀匹配,fantasies 不以 fantasy 开头 → 双路径全失败 → 例句无高亮,失去"语境锚点"的视觉引导。

**修复建议(一行级改动)**: 把 hiColl 的词头分支从 `\bword\w*` 放宽为 `\bword(?:s|es|ed|d|ing|ies)?\w*` 并对 y 结尾词追加 `\bstem(?:i|y)?(?:es|ed|ing)?\b` 变体;或在 gen-mnemonic 的 validate 阶段加"coll 必须能在 en 中被词头前缀规则定位"的硬校验(当前校验只查 coll 可定位,未查屈折)。
