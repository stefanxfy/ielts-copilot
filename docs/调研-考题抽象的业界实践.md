# 调研：正规在线考试的考题与试卷抽象方式

> 日期：2026-08-31
> 目的：为 `docs/数据模型设计.md`（v3.1 · 5 表方案）提供业界参照，验证抽象方向
> 调研对象：IMS QTI 国际标准、Moodle 开源考试引擎、国内主流在线考试系统设计

---

## 1. IMS QTI——国际考题交换标准

QTI（Question & Test Interoperability）是 1EdTech（原 IMS Global）制定的全球最广泛采用的
考试数据标准，Canvas、Blackboard、Moodle、Schoology 等主流 LMS 均支持导入导出。
本质是一个 zip 包：题目以 XML 描述 + 多媒体资源。当前主版本为 QTI 3.0。

### 1.1 层级结构：试卷通过引用组装

```text
AssessmentTest（整卷）
  └─ TestPart（大部分）
       └─ AssessmentSection（分区）
            └─ AssessmentItemRef（引用题库中的题）
                 └─ AssessmentItem（题，独立存储于题库）
```

题库中的 Item 独立存储，试卷通过 ItemRef 引用组装——支持随机组卷、题库复用、
按规则抽题。这是"题库是池子、试卷是组合"范式的标准表达。

### 1.2 Item（单题）的四件套——QTI 最精髓的设计

| 组件 | 职责 | 说明 |
|---|---|---|
| `itemBody` | 题面富文本 | **HTML/XHTML 原文**，可含图片/表格/音视频引用，浏览器直接渲染 |
| `responseDeclaration` | 正确答案声明 | 答案 + 数据形状：cardinality（single/multiple/ordered/record）+ baseType（identifier/string/integer/…） |
| `outcomeDeclaration` | 计分变量 | 分值上限、部分得分、负分等变量声明 |
| `responseProcessing` | 判分规则 | 可引用预置模板（如 choice 判分模板），也可写自定义逻辑 |

### 1.3 两个关键概念

- **Stimulus / Prompt 分离**：stimulus 是多题共享的材料（如阅读文章），prompt 是题干。
  QTI 允许分开建模，但实践中大多数平台不严格区分——"一篇材料配多题"天然嵌在一起；
- **Composite Item（复合题）**：一道 Item 内可含**多个作答位**（如一道完形填空 5 个空、
  一篇文章带 13 道题），每个作答位用 `responseIdentifier` 绑定各自的答案声明——
  这正是雅思"一段文章 + 多题 + 句中挖空"的标准抽象。

### 1.4 题型体系

QTI 2.x/3.0 定义约 20 种 interaction type，各有类名：choiceInteraction（选择）、
orderInteraction（排序）、matchInteraction（匹配）、gapMatchInteraction（拖词填空）、
textEntryInteraction（填空）、extendedTextInteraction（长文本/写作）、hotspot（图上热点）等。
每种题型规定了作答数据的返回形状（单选返回 id，多选返回 id 集合，排序返回有序集合）。

## 2. Moodle——最大开源 LMS 的考试引擎实战

### 2.1 题库与作答引擎严格分离

- **question bank（题库）**：`question` 表只存题目定义——题干、答案、解析、题型、
  默认分值，按 category 组织；
- **question engine（作答引擎）**：存作答行为——`question_attempts`（一次考试中每题一条）
  → `question_attempt_steps`（状态机：todo → complete → gradedright/gradedwrong），
  记录作答演化全过程，支持断线续答、多次作答扣分（penalty）、教师手工批改。

### 2.2 术语纪律（值得借鉴）

- `answers` **专指**教师定义的标准答案；
- `responses` **专指**考生作答；
- `attempt` 专指"考一次试"，单题的作答叫 question session。

命名即语义，避免"answer 到底是标准答案还是考生答案"的歧义。

### 2.3 插件化

- 题型插件（qtype_*）：单选、拖拽、完形、编程题等各自实现渲染与判分；
- 行为插件（qbehaviour_*）：延迟反馈（传统考试）、立即反馈（练习模式）、
  互动式（错了可重试但扣分）。

## 3. 国内主流在线考试系统——题库组卷范式

典型五件套（Spring/SSM + MySQL 系教程与商业系统通用形态）：

```text
subject（科目） ─┬─ knowledge（知识点树，parent_id 层级）
                 │
question（题目表）─ type/difficulty/answer/analysis/score + options(JSON)
                 │
paper（试卷） ─── paper_question（中间表，多对多，带每题分值）
                 │
exam_record（考试记录）── answers(JSON 存考生答案) + score
                 │
result_answers（逐题作答明细）
```

近年演进：
- 题干/选项 **content JSON 化**（MySQL JSON 字段），适配动态题型结构；
- 知识点标签驱动**学情分析**（"哪些知识点正确率低"）；
- 智能组卷（遗传算法/权重随机）依赖题库的难度/知识点元数据。

**核心动机**：题库是"池子"，试卷是"组合"——服务随机组卷与题目跨卷复用。

## 4. 对照本项目的 v3.1 设计（5 表）

| 业界概念 | 本项目对应设计 | 评价 |
|---|---|---|
| QTI itemBody（HTML 原文） | 真题 HTML 不入库，iframe 原样渲染 | 一致，本项目更彻底 |
| responseDeclaration（答案+分值） | answers_json（纯值）+ max_score（questions_json）+ kind 由 type 推导 | 等价，拆得更散但零重复 |
| responseProcessing（判分规则） | scoring.js 的 setEq / textEq / 块题命中 | 等价，代码版而非声明版 |
| Test → Section → ItemRef | papers.questions_json 的 part 分区 | 等价（固定成品卷，无需引用组装） |
| Moodle bank / engine 分离 | papers（定义）/ exam_records（行为） | 同构 |
| exam_record JSON 存答案 | answer_sheet_json | 几乎相同 |
| 知识点标签做学情分析 | part × q_type 维度聚合 | 雅思语境下等价；将来要"同义替换/语法点"维度可加 tags |

### 本项目未照搬的三样及理由

1. **组卷中间表（paper_question）**——业界需要随机组卷与题目复用；本项目考的是
   **固定成品真题卷**，无组卷需求。引入中间表正是被推翻的旧 12 表踩过的坑；
2. **Stimulus/Prompt 分库存储**——QTI 分开是为跨卷复用材料；本项目文章与题目在同一
   HTML 中永不重组，拆开会制造"拆-拼"失真问题；
3. **作答状态机（Moodle attempt_steps）**——为服务端断线续答设计；本项目本地单机、
   交卷一次写入，不需要。

### 结论

本项目的 5 表设计（exam_sets / papers / exam_sessions / exam_records / app_settings）
相当于 QTI / Moodle 抽象在「单用户、固定真题、无组卷」约束下的**最小等价子集**。
四条核心原则与业界一致，无方向性错误：

1. 题面内容以原文存储，渲染不重建；
2. 卷的静态定义与考试动态行为分离（bank/engine 同构）；
3. 标准答案与考生作答命名分离（answers / responses 纪律）；
4. 判分规则与题面解耦（规则可推导，不嵌入内容）。
