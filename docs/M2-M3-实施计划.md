## 卷源格式(schema)

### 顶层结构(标准化 JSON,可直接转 SQL)

```jsonc
{
  "paper": {
    "slug": "a-2025jan-listening-test1",          // 幂等入库键(文件名 = slug)
    "title": "IELTS Mock Test 2025 January · Listening Practice Test 1",
    "category": "A",                              // 'A' | 'G'
    "skill": "LISTENING",                         // 逗号列表;单科写 'LISTENING'/'READING'/'WRITING'
    "source": "ieltsonlinetests.com",             // 卷源出处(可空)
    "durationSec": 1920,                          // 32 分钟
    "status": "PUBLISHED",                        // 'DRAFT' | 'PUBLISHED'
    "meta": { "audioUrl": "/exam-assets/...mp3" } // 卷元(听力的 audioUrl / 写作的字数限制等)
  },
  "sections": [
    { "sectionNo": 1, "sectionType": "LISTENING", "title": "Part 1", "timeLimitSec": 1920 }
  ],
  "passages": [],                                 // 听/作 留空;阅有
  "questionGroups": [
    { "id": "g-q6", "scoreMode": "PER_QUESTION", "minSelect": null, "maxSelect": 2 }
  ],
  "questions": [
    // 单题
    { "number": 1, "type": "FILL_BLANK", "sectionNo": 1,
      "stemHtml": "First name: <span data-qnum=\"1\"></span>" },
    // 块题成员(共享 questionGroupId)
    { "number": 28, "type": "MULTI_CHOICE", "sectionNo": 3,
      "questionGroupId": "g-q28-30",
      "stemHtml": "" }
  ],
  "choices": [
    { "label": "A", "textHtml": "Personal consultation sessions",
      "orderIndex": 1, "questionGroupId": "g-q28-30" }  // 共享给块内所有题
  ],
  "answers": [
    { "questionNumber": 1, "value": "Keiko", "explanationHtml": null },
    { "questionNumber": 28, "value": "D", "questionGroupId": "g-q28-30" }  // 块题时按组提交一次
  ],
  "writingTasks": []                              // 仅作卷有
}
```

### 题型九值(M1 枚举,与 prototype 实际形态对齐)

| 枚举值 | 对应原型形态 | 评分规则 |
|---|---|---|
| `SINGLE_CHOICE` | radio name="q-N" | 精确匹配 |
| `MULTI_CHOICE` | checkbox name="q-N" 单题双选 或 name="q-N-M" 块 | **单题** setEq 严格双对 / **块** maxSelect 命中计分(M1 决策 D) |
| `FILL_BLANK` | input data-num="N" | textEq('/' 备选 + '()' 可选段) |
| `TRUE_FALSE_NG` | select data-num="N"(阅读 28-33) | 精确匹配 |
| `MATCH_*` | select data-num="N"(阅读 14-17 等) | 精确匹配 |
| `SHORT_ANSWER` | input data-num="N" 短答 | textEq |

### 题面 HTML 入库前**全剥**(用户决策)

- jsdom 解析 → sanitize-html(白名单标签 + 白名单属性)
- **去除**:`style`、`class`、所有 `on*=` 事件、`javascript:` href、`<script>`、`<iframe>`
- **保留**:`href`(限定协议 http/https/mailto)、`src`、`alt`、`type`、`name`、`value`、`placeholder`、`title`、`data-num`、`data-template`
- 渲染时(`dangerouslySetInnerHTML`)**再过 DOMPurify 一次**(纵深防御,不是冗余)

### 图片与音频

- 图片:HTML 内 `<img src="./..._files/1.jpg">` → 重写为 `/exam-assets/<slug>/1.jpg` + 拷文件到 `seeds/<slug>/assets/`(M2 阶段)、`public/exam-assets/<slug>/`(M3 build 后);**缺文件 → 拒入库**
- 音频:`paper.meta.audioUrl` 字段,M3 拼装时写入顶栏 audio 元素;文件拷到 `public/exam-assets/<slug>/<mp3>`

### 模板内部结构(原型 reskin 后提取)

3 份模板的差异**只在于顶栏 `{{RIGHT_SLOT}}`**(听 = 音量 UI / 阅 = 空 / 作 = 草稿本)与 `{{BODY}}` 注入形态。**所有 CSS/JS 与原型 `prototype/exam-assets/` 同源**——M3 步骤5 把 `prototype/exam-assets/{css_*.css, js_*.js, nicescroll.min.js, page.js, ...}` 拷到 `src/exam-assets/`(新目录)或直接 `public/exam-assets/`(沿用),postbuild 自动带入 standalone。

### 路由与静态化

- `/papers` 服务端组件:`generateStaticParams` 从 DB 拉所有 PUBLISHED 卷
- `/papers/[slug]` 只读概览:卷元 + sections 列表 + 入口按钮(暂跳到 `/papers/[slug]/test`)
- `/papers/[slug]/test` 服务端组件:从 `process.cwd()/next-server/exam-assets/papers/<slug>/test.html` 读 reskin 后 HTML → 用 dompurify-render 包一层 → `dangerouslySetInnerHTML` 渲染

### 共享 exam-assets

`prototype/exam-assets/` 已经是事实上的资源库。**M3 步骤5** 把这堆拷到工程版 `public/exam-assets/`,postbuild 自动同步到 `next-server/`。**新增卷的图片路径 = `/exam-assets/<slug>/<图>`,postbuild 已覆盖**(M1 步骤6 链路成立)。

## 风险与对策

1. **解析器对每卷 DOM 略不同的鲁棒性**:A 听 / GT 听 / A 阅 / GT 阅 / A 作 / GT 作 DOM 各异;解析器用 `data-num` / `name="q-..."` 锚点统一,DOM 形状差异靠"提取 → 拼装"两段解耦。**每个卷独立 unit smoke test**(每卷 1 个 fixture),跑 CI
2. **DOMPurify 渲染层与 React 18+ 的兼容**:SSR 下 DOMPurify 必须用 jsdom 跑;考虑 `isomorphic-dompurify` 或 react-dom/server 自带的 stream
3. **模板与原型的节点级一致**:render-paper 输出口写一个 diff 脚本,对比 prototype reskin HTML 与工程版 HTML 的**结构等价**(去占位符后),失败则 block merge
4. **题面 HTML 复杂度**:A 作流程图含 SVG / GT 阅含多图片;sanitize-html 默认剥 SVG,需白名单 `<svg>` 与内嵌 `viewBox`(用于图标)
5. **沙箱性 × Node 18+**:`postbuild` 期间 Node ≥ 22 才能跑 better-sqlite3 native 模块;启动.command 已 node 版本闸
6. **回滚路径**:本 plan 落地后的 commit 都在 `M2/M3-styling-decision` 分支;不满足验收 → `git reset --hard m1-complete` 一行回到 M1 干净态;或 `git checkout master`
7. **沙箱性 × 路径**:原型的资源全在 `prototype/exam-assets/`(gitignored 之外),工程版的资源在 `public/exam-assets/`(或 `src/exam-assets/`);M3-4 拷资源时**先核对两边文件数与体积**,避免"少拷了图"
8. **DB schema 兼容性**:M3 不改 schema;若 M3 必须加列(高亮列已在,M3 仅结构定型),走 drizzle-kit generate 出新迁移文件
9. **GT 阅读 Q1 早期瑕疵**:已在 M1 步骤2 更新里记录(现行 answers js Q1 = 普通 `'A,C'`,无块声明);M2-1 解析器要按现行 js 走,不复活旧版
