## 1. 数据模型（src/db/schema.ts 新增段）

### 1.1 枚举与 JSON 契约（与 schema.ts 既有风格一致，先类型后表）

```ts
/** 计划生成来源:确认页徽标用 */
export const PLAN_SOURCES = ["llm", "template"] as const;
export type PlanSource = (typeof PLAN_SOURCES)[number];

export const PLAN_STATUSES = ["ACTIVE", "ARCHIVED"] as const;
export type PlanStatus = (typeof PLAN_STATUSES)[number];

/** 时段四值(phases_json.weeklyTasks[].slot 与 subjectSlots 的值域;availability.slots 已改为范围数组,见 AvailableRange) */
export const TIME_SLOTS = ["morning", "noon", "afternoon", "evening"] as const;
export type TimeSlot = (typeof TIME_SLOTS)[number];

/** 可用时段范围(v2.8) —— availability.slots 元素;HH:mm 24h 制,start<end;
 *  校验:重叠/相邻间隔<30min 合并,最多 6 条;范围→四段按中点归属(段边界由 wake/bed 推导) */
export interface AvailableRange {
  start: string;
  end: string;
}

/** 周任务类型 —— 与 study_activities 统计列一一对应 */
export const TASK_TYPES = ["words", "listening", "reading", "writing", "speaking", "set"]
  as const;
export type TaskType = (typeof TASK_TYPES)[number];

/** study_plans.availability_json —— 这轮备考的节奏(换计划即换;申报每日量也在此) */
export interface PlanAvailability {
  /** 全职/在职 */
  mode: "fulltime" | "working";
  /** 每天可投入小时数(0.5 步进) */
  dailyHours: number;
  /** 可安排时段(v2.8:精确范围数组;向导勾选四段带默认范围可精确修改;空数组 = 任务不填时段渲染灰色) */
  slots: AvailableRange[];
  /** 用户申报的每日背词数(可选;未填由默认模板/LLM 定。v2.5 并入,原 daily_goals_json 列删除) */
  dailyWords?: number;
  /** 英语水平自述(v2.6,可选自由文本;限 200 中文字符以内——前端 maxLength 200+计数提示,后端超长校验拒绝;原样注入 LLM 提示词;默认模板不解析自由文本) */
  englishLevel?: string;
}

/** study_plans.target_scores_json —— 四科目标,缺省项读取时用总分−0.5 兜底 */
export interface TargetScores {
  listening?: number;
  reading?: number;
  writing?: number;
  speaking?: number;
}

/** study_plans.phases_json 元素 —— 分阶段方案(LLM 与默认模板同一形状) */
export interface PlanPhase {
  /** 阶段名:基础期/强化期/冲刺期(LLM 可自拟,渲染原样展示) */
  name: string;
  /** 相对周数(从计划创建周起算第 1 周),各阶段连续不重叠覆盖 1..N */
  weeks: number[];
  /** 阶段重点,≤20 字 */
  focus: string;
  /** 周任务模板 */
  weeklyTasks: {
    type: TaskType;
    /** 量:words=个/天,其余=套(次)/周 */
    count: number;
    unit: "个/天" | "套/周" | "次/周";
    /** 建议时段;无偏好且无可时段时缺省 */
    slot?: TimeSlot;
  }[];
}

/** app_settings.study_preferences —— 个人习惯(人的属性,跨计划持久) */
export interface StudyPreferences {
  /** 作息 "HH:MM";缺省 07:00 / 23:00 */
  wakeTime?: string;
  bedTime?: string;
  /** 各科偏好时段,键 ∈ TASK_TYPES,值 ∈ TIME_SLOTS;未声明的不出现 */
  subjectSlots?: Partial<Record<TaskType, TimeSlot>>;
}

/** app_settings.punch_rules —— 打卡规则(可配置;默认值兜底,设置页可改) */
export interface PunchRules {
  /** 当日交卷达标线(默认 1) */
  submissionMin: number;
  /** 当日背词达标线(默认 5) */
  wordsMin: number;
  /** 双达标才满卡(默认 true;false = 任一达标即满卡) */
  bothForFull: boolean;
  // 后续可扩 minutesMin(学习时长)等,只加键
}

/** study_journals.ai_summary_json —— AI 昨日总结 */
export interface AiSummary {
  summary: string;
  suggestions: string[];
  basedOn: { submissions: number; words: number; journalExcerpt: boolean };
  model: string;
  generatedAt: string;
}
```

### 1.3 与规划文档 v2.4 的两处代码级细化

1. **`plan_start_week_monday` 新增列**：phase.weeks 是相对周数，必须有锚点。
   值 = 计划创建那周的周一日期（`YYYY-MM-DD`）。渲染「今日任务」时：`floor((今天 − 锚点)/7) + 1 = 当前周号` → 定位阶段。调整计划改日期/目标时**锚点不动**（已过的周不改写历史），只重排锚点之后的周。
2. **`generated_by` 独立列而非塞进 phases_json**：phases_json 保持纯数组（与 LLM 输出/默认模板形状零转换），来源徽标是「这份计划的属性」不是「任务内容」，单列更利查询。

### 1.4 命名勘误（✅ 用户已确认 2026-09-01）

- `exam_set_submission_count` → **`exam_set_completion_count`**：套卷行不是「交卷」动作而是「整套完成」事件（三科交齐才算 1），与 finalize 语义对齐，避免「交卷」双关（单科交卷 vs 套卷完成）。规划文档 §4.3/§5.2/§6 五处已同步。
- 其余字段名照旧（listening/reading/writing/speaking_submission_count、memorized_word_count、activity_date、journal_date）。

## 4. 关键算法

### 4.1 当前周号定位（checklist/阶段进度共用）

```
anchorMonday = plan.plan_start_week_monday
weekNo = floor(daysBetween(anchorMonday, today) / 7) + 1   // today < anchor 不会发生(锚点=创建周)
phase = phases.find(p => p.weeks.includes(weekNo))
```

### 4.2 勾选判定（查询时计算）

- words：当日 memorized_word_count ≥ count
- listening/reading/writing/speaking/set：**本周累计**（周一为周首）对应列合计 ≥ count
- speaking：P8 前恒不勾不红，灰色「暂无追踪」（数据列就绪即自动转正常判定，零改动）

### 4.2.1 打卡判定（配置驱动，v2.5）

规则**不硬编码**：读取 `app_settings.punch_rules`（未配置用默认值），判定在查询时计算：

```ts
const rules = readPunchRules(); // { submissionMin: 1, wordsMin: 5, bothForFull: true } 兜底
const submitted = 五科 submission + exam_set_completion 合计;
const punched =
  (submitted >= rules.submissionMin ? 1 : 0) + (words >= rules.wordsMin ? 1 : 0);
// punched >= 1 → 打卡;bothForFull ? punched >= 2 : punched >= 1 → 满卡
```

- 设置页新增「打卡规则」卡片（submissionMin / wordsMin / bothForFull 三项，数值上下限校验：1–20 / 1–100）
- 扩展方式：PunchRules 接口加键（如 minutesMin 学习时长线），判定函数加对应分支——**日历渲染与 activities 表结构零改动**
- 日历/学习情况统计每次查询现读规则 → 改配置**立即生效**，历史日的打卡态也按新规则即时重算（规则是「当前视角」不存快照，避免历史固化无法追溯调整）

### 4.3 AI 昨日总结触发（✅ 含手动重跑，用户已确认）
