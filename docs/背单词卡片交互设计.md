# 背单词卡片交互设计（认词卡 + 默写卡）

> **文档定位**：本文档记录背单词复习层的**卡片交互设计定稿**——认词卡与默写卡（三型）的卡面构成、提示阶梯、判分音效、导航规则、原型设计思想与踩坑注意事项。
> 数据层设计（word_progress 单轨状态机、FSRS 调度、编辑距离阈值依据、素材回退链）见 `docs/背单词数据模型设计.md` §8/§10；判定规则与本文档共享，冲突时以本文档（原型已实测）为准。

## 1. 认词卡（stage = recognize）

### 1.1 卡面结构（自上而下）

```
┌─────────────────────────┐
│       配图（有图版）        │   无图版不渲染配图，单词升为主视觉
│   单词   /音标/ 🔊        │   ← 音标+裸喇叭悬挂词右侧（有图版）/ 词正下方（无图版）
│   例句（斜体英文）    🔊    │   ← 例句裸喇叭可朗读
│   （中文释义 — 点击模糊/不认识后展开）│
└─────────────────────────┘
  ◀  卡片  ▶     ← 方向键悬浮卡片两侧，垂直对齐单词行中心
[ 不认识 ] [ 模糊 ] [ 认识 ]  ← 三键评分在卡下方
```

- **裸喇叭范式**：发音按钮无圈、无底色、无边框，纯主题色喇叭图标（`--primary`），hover 放大 1.08 / active 缩小 0.94。全项目所有发音按钮统一此样式，禁止圆形底托。
- **卡面零说明文字**：卡内不出现任何操作指引文案（如"点击喇叭听读音"），交互自解释。

### 1.2 评分与状态机联动

| 操作 | 行为 |
| --- | --- |
| **认识** | streak +1；连续 2 次认识 → stage 升 spell；**自动跳下一个词** |
| **模糊 / 不认识** | streak 清零；若已升 spell 则降回 recognize；卡面**展开中文释义**（reveal 态） |

- 释义展开属"揭示"：模糊/不认识后才能看到中文，与默写卡的"先猜后揭示"思想一致——反馈在被 require 的动作之后出现。

### 1.3 导航（方向键）规则

- **右箭头（下一个）**：仅当当前词「背过」（点过认识/模糊/不认识任一键）后解锁——防止跳词刷量；背过的词回来后随时可再跳。
- **左箭头（上一个）**：首词置灰，其余始终可用——允许返回重背。
- **键盘 ←/→** 等效按钮；输入框聚焦时方向键留给光标移动，不抢。
- **箭头垂直定位**：JS 实测 `getBoundingClientRect` 把箭头钉在**单词行几何中心**（非百分比估算）；图片 `load` 完成后与 `resize` 时重校（图片未加载时高度为 0，会导致定位失真）。

### 1.4 无图变体（认词卡·无图）

- 无配图时单词成为主视觉：基准 **52px**、最小 40px，按「词宽 ≤ 卡内宽 − 36px」逐级收缩字号（`fitPlainWord`）。
- 音标 + 喇叭移到**单词正下方居中**（有图版是悬挂词右）。
- 单词组绝对定位铺满整卡垂直居中（`inset:0`）；例句+释义钉底 `z-index:1`；**揭示态若与底部内容重叠，JS 实测重叠量把单词组整体上移让位**（+10px 呼吸间距）。

## 2. 默写卡三型（stage = spell）

### 2.1 三型定义

| 型 | 卡面主刺激 | 说明 |
| --- | --- | --- |
| **视觉型** visual（40%） | 配图 | 图上锁死不带文字（配图即剧透防线，见数据模型文档 §6.1） |
| **听觉型** audio（30%） | 大裸喇叭 | 进入卡面**自动播读音 1 次**（350ms 延时），喇叭可反复点；自动播按「卡型：单词」独立标记，只播一次 |
| **语境型** ctx（30%） | 例句挖空 + 配图 | 挖空处显示 `______` 下划线；**不显示例句中文翻译** |

- 三型**加权随机**出现（顶部「随机默写卡」按钮），比例存 `app_settings.vocab_spell_mix` 可调，默认 40/30/30。
- **卡面零说明文字**：型别标签、提示语（"根据配图拼出这个单词"等）、辅助提示文字一律不上卡面。

### 2.2 输入交互

- **单行下划线输入**：无外框、无逐字母格、无字母数提示；`border-bottom` 底线 + 居中等宽字体。
- 仅接受小写字母（自动过滤）；**不换行、不限长度**，超宽由输入行横向滚动。
- 自动聚焦；**回车 = 提交判分**。
- **草稿保留**：打字中途点提示导致重渲染时，未提交草稿恢复（`s.draft`）——点提示不应毁掉用户已打的内容。

### 2.3 提示阶梯（核心定稿）

提示按钮在**卡下方**（卡外，与提交钮并排，与卡同宽）。每卡最多点 2 次，逐级揭示，不可跳级、不可收回：

| 次序 | 视觉型 / 语境型 | 听觉型 |
| --- | --- | --- |
| 第 1 次「提示」 | **读音**（自动播 1 次 + 裸喇叭可复听）+ **音标** | **配图升级为主视觉**：大图居中（`.vis-img`），音标 + 裸喇叭在图正下方——布局与视觉型一级提示完全同款（喇叭保留：提示后"听"不再是唯一通道） |
| 第 2 次「提示」 | **中文释义** | **中文释义**（图 + 音标 + 喇叭保持，释义块在下方追加） |

> 听觉型一级提示是**整卡重渲染**：大图直接替换主刺激区的大喇叭（复用视觉卡 `.vis-img` 样式），而非在原喇叭下方塞一张小图——保证三型提示后的视觉层级一致。

- **提示状态按「卡型：单词」复合键独立**（`spellKey = typeId:wordId`）：视觉型给 abandon 点过的提示，切到听觉型同词归零，切回视觉型保留——三型互不污染，同一型不同词也互不影响。

### 2.4 「查看答案」（两级用尽后）

两级提示都点过后，提示按钮文字变**「查看答案」**，点击效果：

1. 答案单词**填入输入行**（红色 `revealed` 态，**锁定不可修改**）；卡面不再重复渲染"正确拼写"块（答案已在输入行，展示一次即可）。
2. **提交按钮禁用**——只能通过方向键 上一个/下一个 离开。
3. **语义 = 不认识**：播放错误音效、答题流水记 `reveal`、stage 降回 recognize、streak 清零（FSRS 走 Again）。

> 设计动机：查看答案是"我猜不出来了"的自白，与判错（至少尝试过）区分开——它是最强的负面信号，直接跌落，不给 Hard 缓冲。

### 2.5 判分（回车提交）

提交那一刻才判定，输入过程可自由修改：

**判对**（逐字母一致）：
- 音效按提示次数分级（WebAudio 合成，无外部音频资源）：
  - 0 提示 → **Perfect**（上行三连音 660/880/1100Hz）
  - 1 提示 → **Great**（上行双音 580/780Hz）
  - ≥2 提示 → **Good**（单音 520Hz）
- 卡面徽标 `✓ Perfect/Great/Good`；**900ms 后自动跳下一个词**（定时器校验 wordId，期间用户手动跳过则不双跳）。
- stage 联动：0~1 次提示答对 → 停留 spell；**两级提示用满后答对 → 降回 recognize**（提示用尽说明记忆不牢，见 §4 待拍板项）。

**判错**（编辑距离 ≤2 → Hard 模糊 / >2 → Again 不认识）：
- 低频下行错误音效（220→165Hz square）。
- **全揭示**：提示区补全（音标/图/释义）+「正确拼写」红框块；输入行回显**用户刚才的拼写**并标红（保留错误现场，逐格标对错的逐字母格方案已废弃）。
- **输入锁定**，提交钮变「下一个」；stage 降回 recognize、streak 清零。

### 2.6 导航放行

- **提交过本词（对错均可，含查看答案）→ 左右箭头解锁**——与认词卡"点过评分键才放行"一一对应。
- 键盘 ←/→ 全局监听（一次绑定，防重复），输入聚焦时不抢；查看答案态输入已禁用失焦，方向键畅通。

## 3. 原型设计思想与注意事项（踩坑沉淀）

1. **卡面零说明文字是铁律**。所有操作指引靠交互自解释（喇叭=播放、下划线=输入、回车=提交）。终验方式：扫描三型卡面全文，指定文案零残留。
2. **裸喇叭范式全局统一**：无圈无底色，主题色描边图标。曾两次返工（圆钮没摘干净），新增发音按钮时直接复用 `.play-bare`。
3. **方向键定位必须 JS 实测，不信百分比**：`getBoundingClientRect` 取单词行中心再减按钮半高；图片 `load` + `resize` 两个时机重校（图片未加载时按 0 高计算会错位 30%+）。
4. **例句挖空要两段式替换**：先 `replace` 成 `@@BLANK@@` → 整句 `esc` 转义 → 再把占位符换成 `<span class="blank">`。直接插 span 再 esc 会把标签转义成可见文本。
5. **重渲染型 UI 必须考虑草稿/状态保留**：点提示会重渲染整卡，输入草稿、提示级别、判分态都存在 state 里按需恢复，不依赖 DOM 存活。
6. **自动跳词的定时器要校验 wordId**：900ms 等待期内用户手动点了下一个，定时器回调发现 `state.wordId !== fromWord` 直接 return，防双跳。
7. **音效用 WebAudio 现场合成**（`OscillatorNode` + 指数衰减包络），零外部资源、零版权问题；错误音刻意用低频 square 波与正确音的清亮 sine 区分。
8. **提示/判分状态按复合键隔离**：`卡型:单词` 键设计让三卡型互不污染，这是"三型是同一词的不同侧面"思想的直接体现。
9. **逐字母格方案已废弃**：曾按参考截图做过底边线字母格 + 隐形 input 承接击键，坑多（重渲染清子节点、格数 NaN、判错回显复杂），最终收敛为单行下划线输入——更简单也更符合"一条线就行"的直觉。
10. **状态机语义嵌在交互里**：认识自动跳词、查看答案禁提交、判错锁输入——每个负面信号都有不可逆的 UI 锁定，防止用户"再改改就对了"式自我欺骗（拼写训练的价值在第一反应）。
