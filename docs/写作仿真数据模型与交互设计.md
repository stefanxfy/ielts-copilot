## 1. 定位与边界

| # | 决策 | 来源 | 落点 |
|---|---|---|---|
| 1 | **定位 = 雅思机考写作环境仿真**，不是写作教学 | 用户 2026-09-11 拍板 | §3 交互 |
| 2 | 素材 = papers 真题卷结构化题干（146 套 100% 可解析，已实测） | 2026-09-11 调研 | §2.1 / §5 脚本 |
| 3 | 无限练习：题目随机抽或自选，练完可再抽 | 用户明确 | §3.1 |
| 4 | **仿真三无**：无拼写检查红线、无自动纠正/联想、无词数封顶提示——与机考编辑器一致 | 设计判断（差异化的核心） | §3.2 |
| 5 | 常驻**实时字数统计**（Task 2 ≥250 / Task 1 ≥150）+ 倒计时（40 / 20 分钟） | 机考界面要素 | §3.2 |
| 6 | 边界：不做范文、不做模板、不做批改评分（观察使用后再定是否接 LLM 反馈） | 设计判断（先简后繁） | §6 后置 |
| 7 | **一期只做 A 类作文**（Task 2 议论文），G 类书信整体后置 | 用户 2026-09-12 拍板 | §2.1 / §3 / §5 |

**与打字练习的分工**：打字练习练"手指"（有标准答案的跟打）；写作仿真练"输出"（无标准答案的自由写作环境）。两者共用整篇计时/字数的肌肉记忆，但编辑器形态完全不同——打字是逐字对照，写作是纯文本域。

## 2. 数据模型（2 张新表）

### 2.1 `writing_prompts`：真题题库（静态，脚本导入）

```ts
export const WRITING_CATEGORIES = ["A", "G"] as const; // Academic / General Training

export const writingPrompts = sqliteTable("writing_prompts", {
  /** 幂等键 = papers.exam_id + 任务号,如 "a-2025jan-writing-test1:t2" */
  promptId: text("prompt_id").primaryKey(),
  /** 1=Task 1 / 2=Task 2 */
  taskNo: int("task_no").notNull(),
  category: text("category", { enum: WRITING_CATEGORIES }).notNull(),
  /** 题干正文(纯文本,G 类书信含 bullet 要点,换行分隔) */
  promptText: text("prompt_text").notNull(),
  /** 最低词数(150/250) */
  minWords: int("min_words").notNull(),
  /** 建议用时(分钟:20/40) */
  timeSuggest: int("time_suggest").notNull(),
  /** A 类 Task 1 图表图(papers 静态资源路径;书信/Task 2 为 NULL) */
  imageUrl: text("image_url"),
  /** 出处 { examId, paperTitle } */
  sourceRefJson: text("source_ref_json", { mode: "json" })
    .$type<{ examId: string; paperTitle?: string }>()
    .notNull(),
  createdAt: int("created_at", { mode: "timestamp" })
    .notNull()
    .default(sql`(unixepoch())`),
});
```

**要点**：
- 题干为**纯文本**——解析时剥 HTML 标签，G 类书信的 bullet 要点用换行拼接
- A 类 Task 1 带图表图（`img` 路径指向 papers 静态资源，已有 `/exams/**` 静态托管），题目卡直接显示；**一期仿真编辑器只做 Task 2（议论文）+ G 类 Task 1（书信）**，A 类 Task 1（看图写作）列为 P2——图表题的手写场景价值低于议论文
- `promptId` 幂等 = 可重复跑导入脚本（`--fill` 跳过已有，对齐 reading-import 惯例）

### 2.2 `writing_sessions`：写作练习记录（动态，用户产出）

```ts
export const writingSessions = sqliteTable("writing_sessions", {
  id: int("id").primaryKey({ autoIncrement: true }),
  /** FK → writing_prompts,RESTRICT(题库不删) */
  promptId: text("prompt_id")
    .notNull()
    .references(() => writingPrompts.promptId, { onDelete: "restrict" }),
  /** 提交时词数(服务端按 /\b[a-zA-Z']+\b/g 重算,不信任客户端) */
  wordCount: int("word_count").notNull(),
  durationSec: int("duration_sec").notNull(),
  /** 是否达到最低词数(服务端算,只标记不拦截) */
  reachedMin: int("reached_min", { mode: "boolean" }).notNull(),
  /** 用户正文(回看/将来接批改的原料) */
  content: text("content").notNull(),
  finishedAt: int("finished_at", { mode: "timestamp" })
    .notNull()
    .default(sql`(unixepoch())`),
}, (t) => [index("idx_writing_sessions_finished").on(t.finishedAt)]);
```

**要点**：
- **正文必须存**（与打字不同——写作没有"标准答案"，内容本身就是数据），将来接 LLM 批改也靠它
- `wordCount` 服务端重算（口径唯一：连续字母串计 1 词，撇号内联）；`reachedMin` 只标记不拦截——机考也不阻止你少写
- 中途退出**不入库**（与打字同口径），但有「存草稿」显式动作时入 `content` 未完成态？——**不做**，一期保持简单：交卷才算数，刷新即弃（真机考也没有草稿箱）

## 3. 交互设计

### 3.1 流程（进入即写）

- 路由 `/writing`，顶部导航「写作练习」。
- **进入默认 A 类 Task 2 随机抽题**（未练过的优先，一期 category 固定 A）；题目卡右侧「换一题」随机换、下拉可自选（显示 是否练过 + 上次词数）。
- 题目卡：类别徽标（A/G）· Task 号 · 最低词数 · 建议用时 · 出处（哪套真题）；A 类 Task 1 附图表图。

### 3.2 仿真编辑器（核心）

- **纯 textarea**（`spellCheck=false` + `autoCorrect/off` + `autoCapitalize/off`）：无红线、无联想、无自动大写——机考就是一块白板
- 顶部常驻实时条：**字数（大字）/ 最低词数进度条 / 倒计时 / 段落数**
  - 倒计时从首键起算；**到点只变红提示，不强制交卷**（机考到点自动收卷，但练习环境强制收会丢字，选择提示制）
  - 字数进度条三态：<min 灰 → ≥min 墨绿 → 超出建议区间（Task 2 >350）琥珀提示「写多了，考场上这是时间风险」
- 右下常驻：**重置 / 交卷**
- 交卷 → 统计卡内联展开：词数 / 用时 / 输出速度（词/分钟）/ 段落数 / 是否达标 → 「再写一篇（换题）」「重写本题」；正文入库可回看

### 3.3 与打字练习的入口互通

- 打字练习的「写作仿真」观念入口不设——两个功能导航平级，不互相嵌
- 统计口径沿用 WPM 概念：输出速度 = 词数 / 分钟（不是击键 ÷5，写作看真词数）

## 4. API（2 个新接口）

| 接口 | 方法 | 职责 |
|---|---|---|
| `/api/writing/prompts` | GET | 抽题（`?random=1&taskNo=2`；一期 category 固定 A，G 类数据入库但不启用）+ 清单（含已练次数/上次词数） |
| `/api/writing/sessions` | POST | 交卷（promptId/durationSec/content）；**服务端重算 wordCount/reachedMin** 入库 |

## 5. 素材导入脚本

`scripts/writing-import-paper.mjs`（对齐 reading-import 惯例）：

- 遍历 `papers WHERE subject='writing'`（146 套）→ 读 `assets_json.entry` 指向的 `writing.html`
- 按 `test-contents__title` 切 Task 1 / Task 2 区块；题干取 `p.Indent1`（剥标签）；G 类书信取 `<strong>` 段 + bullet 列表拼换行
- 已实测：Task 2 抽取成功率 100%（12/12 抽样全对），A 类 Task 1 另存 `imageUrl`
- 参数：`--fill`（跳过已有 promptId 幂等）、`--dry`（只打印不写库）

## 7. 开放问题（2026-09-12 全部定案）

1. **倒计时到点行为 → 提示制**（维持当前设计）。理由：练习环境强制收卷会丢字，而且「对时间的感知」本身就是练习目标——到点红字提示 + 可以继续写，写完在统计卡里能看到「超时 N 分钟」，比强制收卷更能暴露问题。
2. **G 类书信格式提示 → 随 G 类整体后置**，届时再议（用户已拍板 G 类先不做）。
3. **下拉降噪 → 采用**：未练过的优先随机，下拉按「未练在前 + 练过按最近练习时间降序」（对齐打字练习下拉已验证的排序经验），146 题全量但顺序即信息。
