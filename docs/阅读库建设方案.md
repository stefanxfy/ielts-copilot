## 结论（TL;DR）

- **分级**：自建四级体系 L1–L4（映射 CEFR 与雅思阅读 band），定级以**客观文本指标**（Flesch / 句长 / 词频覆盖率）为主、**LLM 复核**（CEFR / 话题 / 摘要 / 生词表）为辅，人工抽检兜底。
- **素材**：主力三源——**Breaking News English**（每课 7 级改写 + 音频，最贴合「分级+音频」）、**News in Levels**（3 级 + 音频）、**DreamReader**（分级阅读 + 音频）；长文/学术向解锁主流刊物 **New Scientist / Aeon / Scientific American / Smithsonian / National Geographic**（本机实测可达），另加 Gutenberg、NPR、Guardian API。VOA / BBC / 维基百科 / 经济学人当前网络不可达，列为需代理的备选源。**GitHub 开源语料**可直接补规模：OneStopEnglish（189×3 级同文三档，CC BY-SA）、ielts-ai-dataset（按 band 分级的 AI 雅思题库）等（§3.3）。
- **音频（双轨）**：实测确认原生音频源全部是**整篇一 mp3**（按文章/级别版本，无段落分段）→ 有原生音频的源**优先下载原版**（真人朗读质量上限），用 **faster-whisper 句级时间戳对齐**实现逐句高亮/点句重听；无音频源才用 **edge-tts 段落级合成**兜底（复用 `synth-audio-xdf.mjs` 幂等骨架）。
- **逐句翻译**：LLM 逐句翻译 + 三重强校验（句数一致 / 编号回传 / 长度比异常报警）保证「逐句对得上」，阅读器逐句对照——「听一句·读一句·看一句译文」的精听式体验。
- **数据**：新增 2 表（`reading_articles` 定义层 + `reading_progress` 学习层），正文入库支持 SQLite 全文检索；素材源 JSON 留 `data/reading/raw/` 作血缘；音频落 `public/audio/reading/` 并 **gitignore**（不进 git 不进默认打包）。
- **节奏**：R1 地基 → R2 种子管线（40–60 篇跑通全链）→ R3 阅读 MVP → R4 规模化（300–1000 篇）→ R5 学习闭环。首批 100 篇音频约 200–400MB，千篇约 2–4GB。

## 二、难度分级体系

### 2.1 四级档位（定稿口径）

| 档位    | CEFR   | 雅思阅读参照   | 词数/篇     | Flesch RE | 文体          |
| ----- | ------ | -------- | -------- | --------- | ----------- |
| L1 入门 | A2–B1  | ~4.5–5.5 | 200–400  | ≥70       | 新闻简讯 / 生活短文 |
| L2 基础 | B1+–B2 | ~5.5–6.5 | 400–700  | 60–70     | 新闻 / 科普     |
| L3 进阶 | B2–C1  | ~6.5–7.5 | 700–1000 | 50–60     | 科普 / 议论文    |
| L4 冲刺 | C1–C2  | ~7.5+    | 900–1300 | <50       | 学术向长文       |

> 自带原生分级的源（BNE 的 7 级 / NiL 的 3 级）先映射到 L1–L4（BNE L0–L2→L1、L3–L4→L2、L5→L3、L6→L4；NiL 1/2/3→L1/L2/L3），再经定级管线校准，**以管线结果为准、原生等级仅作提示**。

### 2.2 定级管线（三步）

1. **客观指标（自动，确定性）**：Flesch Reading Ease / FK 年级、平均句长、长词比；词汇覆盖率——复用项目已有 ECDICT 词频资产（`build-ecdict-index.py` 索引，BNC/COCA 词频），统计「词频排名 >8000 的低频词占比」。
2. **LLM 复核（已配置的 LLM provider，批量限速）**：输出 CEFR 档、话题分类（受控词表）、60 字中文摘要、雅思核心生词表 glossary（词 + 音标 + 中文释义，生词直接来自文中）。客观指标与 LLM 结论冲突时以客观指标为准，LLM 位移不超过一档。
3. **人工抽检**：每批抽样 10% 复核等级与话题；列表页支持手动改级（写回 `reading_articles.level`，并在血缘 JSON 留痕）。

## 四、音频生产方案（双轨：原生音频优先，TTS 兜底）

> 2026-09-08 实测结论：**原生音频全部是「整篇一 mp3」**（按文章/级别版本，无段落分段）——BNE 课程直链模式 `breakingnewsenglish.com/YYMM/<slug>.mp3` 实测可达（HTTP 206），NiL 音频由播放器 JS 注入但确认存在（每级一轨）。要拿到「逐段/逐句高亮」必须自己做时间对齐，故设双轨：

### 4.1 轨 A · 原生音频下载 + whisper 句级对齐（有音频源的主路径）

- BNE / NiL / DreamReader / SciAm 播客等原生音频源，`reading-fetch` **直接下载原版整篇 mp3** → `public/audio/reading/{articleId}/full.mp3`（真人朗读，质量上限，连读/弱读/数字读法都是真实语料）。
- `reading-align.mjs`：**faster-whisper**（本地 CPU，small/base 模型足够）转写 full.mp3 得**句级时间戳** → 与文章句切结果模糊文本匹配（编辑距离/词窗对齐，容忍转写与原文的出入）→ 产出**句级起始秒数组** `timeline_json`（与 `sentences_json` 一一对应）。
- 匹配率 <90% 标记「对齐失败」，**降级为整篇连播**——阅读、翻译不受影响，仅缺句级高亮；后续可换 medium 模型重跑。
- 阅读器效果：逐句高亮 + 点句重听（seek 到该句起始秒）+ 整篇连播三合一。

### 4.2 轨 B · edge-tts 段落级合成（无音频源兜底）

- 无音频源（Guardian / Gutenberg / 维基等）复用 `synth-audio-xdf.mjs` 全套工程手段：幂等（文件 >1KB 跳过）、并发 4、每 100 任务 flush、失败清单续传补跑。
- **只合成段落音频，不合成整篇**：`public/audio/reading/{articleId}/p01.mp3 …`，落盘回写 `paragraphs_json` + `audio_status`（NONE/PARTIAL/DONE）。
- **关于「edge-tts 效果会不会不好」**：
  - 音色即 Azure Neural（微软神经音色），免费 TTS 第一梯队；本项目背单词 3575 词 + 例句已在用（Andrew/Emma，-8% 降速），质量已经过验证；
  - 真正的短板是**长文连续朗读韵律偏平**、单次请求有文本长度上限——**段落级合成恰好同时规避两者**（每段短文本，节奏自然、停顿可控）；
  - 与真人朗读仍有可感差距（这是设轨 A 的核心原因）：个别专名/缩写可能怪读，reading-check 抽样试听把关；
  - 音色：默认续用项目定稿的 `en-US-AndrewMultilingualNeural`，或雅思语境英音 `en-GB-SoniaNeural`（实施前小样试音定稿，对齐 2026-09-03 试音流程）；变速前端做，不重复合成。

### 4.3 体积估算与分发

- 两轨同数量级：L1/L2 篇均约 2.5 分钟（≈1–2MB），L3/L4 篇均约 7 分钟（≈3–5MB）。
- 首批 100 篇 ≈ 200–400MB；千篇 ≈ 2–4GB。`public/audio/reading/` **gitignore**；打包默认排除，`--with-audio-reading` 开关按需携带。
- 轨 B 音频可由 TTS 从 DB 正文随时复现；**轨 A 原生 mp3 不可复现**，磁盘紧张时优先保留轨 A。

## 五、逐句对照翻译

### 5.1 句切一次，处处复用

- 导入时完成**句切**（句边界规则 + 缩写/小数/省略号保护），全篇平铺 `sentences_json`（每句带段落归属 `p`）；段落 = 句归组，**正文渲染、翻译对照、whisper 时间对齐共用同一份句序**，杜绝多处切句错位。

### 5.2 LLM 逐句翻译（保证「对得上」）

1. **编号回传**：prompt 按编号列出英文句（附本篇 glossary 锁定术语译法），要求**按相同编号逐句回传**，禁止合并/拆分/漏句。
2. **三重强校验**（不通过不入库，进失败清单）：
   - 句数一致：回传条数 = 原句数；
   - 编号对齐：逐条按编号匹配，不依赖返回顺序；
   - 长度比报警：单句 zh/en 字符比 <0.4 或 >2.0 视为可疑 → 自动重翻；仍失败标记「该句暂无译文」降级展示，不阻塞整篇入库。
3. **术语一致**：glossary 与专名译法注入 prompt，人名/地名全篇统一。
4. **抽检与修正**：每批抽 10% 人工审校；阅读器内每句可「报错重翻」（走同一 LLM 通道，写回前过同样校验）。

### 5.3 与音频的联动（精听式体验）

- 轨 A 句级时间戳 + 句级译文 =「**听一句 → 高亮一句 → 看一句译文**」，即听力精听的阅读版；
- R5 增强：整句译文隐藏自测（遮译文回忆句意）、点句重听与生词本联动。

## 六、数据模型（草案，遵循「静态定义 / 动态学习」切开原则）

```ts
/** 阅读库难度四档（映射见方案 §2.1） */
export const READING_LEVELS = ["L1", "L2", "L3", "L4"] as const;

/** 话题受控词表（雅思阅读高频题材 + other 兜底） */
export const READING_TOPICS = [
  "science", "environment", "education", "health", "society",
  "technology", "culture", "history", "business", "other",
] as const;

/** audio_status 三态：NONE 未合成 / PARTIAL 缺段 / DONE 齐套（两轨任一到位即可 DONE） */
export const AUDIO_STATUSES = ["NONE", "PARTIAL", "DONE"] as const;

/** reading_articles.sentences_json 单条（全篇句序平铺，句切在导入时一次完成） */
export interface ReadingSentence {
  /** 所属段落序（0 起），渲染层按 p 分组还原段落结构 */
  p: number;
  /** 英文原句 */
  en: string;
  /** 中文译文（LLM 逐句翻译，与 en 一一对应；翻译失败可暂缺） */
  zh?: string;
}

/** reading_articles.paragraphs_json 单条（段落与轨 B 段落音频对齐，键序即段落序） */
export interface ReadingParagraph {
  /** 段落纯文本（= 该段 sentences 按 p 归组拼接，导入时校验一致性） */
  text: string;
  /** 轨 B 音频 web 路径 /audio/reading/<articleId>/pNN.mp3（未合成时缺省） */
  audio?: string;
}

/** reading_articles.glossary_json 单条（LLM 提取的雅思核心生词） */
export interface ReadingGlossaryItem {
  word: string;
  phonetic?: string;
  cn?: string;
}

readingArticles（1 行 = 1 篇文章，articleId 幂等导入键，同 examSetId/wordBooks.bookId 模式）:
  articleId text PK          -- 如 "bne-20260908-l3-eu-carbon"
  title / source / sourceUrl -- 展示名 / 来源标识 / 原文链接（血缘）
  level text                 -- READING_LEVELS
  topic text                 -- READING_TOPICS
  cefr text?                 -- "B2" 等（LLM 复核产物，展示用）
  wordCount int              -- 导入时统计
  estDurationSec int         -- 按 wordCount/150wpm 估算，列表展示
  body text                  -- 纯文本正文，\n\n 分段（渲染层切段）
  sentencesJson json?        -- ReadingSentence[]（句切 + 逐句中文翻译）
  audioFull text?            -- 轨 A 整篇音频 /audio/reading/<articleId>/full.mp3（原生音频源）；null = 走轨 B 段落音频
  timelineJson json?         -- 轨 A 句级起始秒数组 [0, 8.3, ...]（whisper 对齐产物，与 sentencesJson 一一对应；对齐失败 = null，整篇连播）
  paragraphsJson json        -- ReadingParagraph[]（段落↔轨 B 段落音频对齐）
  audioStatus text           -- AUDIO_STATUSES
  glossaryJson json?         -- ReadingGlossaryItem[]
  summaryZh text?            -- 中文一句话摘要（列表卡片）
  publishedAt text?          -- 源发布日（可排序，新闻时效性）
  createdAt / updatedAt

readingProgress（1 行 = 1 篇的学习进度，学习层，删文章级联清）:
  articleId text FK→readingArticles ON DELETE CASCADE, UNIQUE
  status text                -- "READING" | "FINISHED"
  lastParagraph int          -- 续读定位（第 N 段，0 起）
  totalReadSec int           -- 累计阅读/收听时长（打卡口径）
  openedAt / finishedAt / updatedAt
```

- 全文检索（R5 可选）：SQLite **FTS5** 虚表 `reading_fts(article_id, title, body)`，支撑阅读器内查词上下文与库内搜索。
- 打卡接入：`study_activities` 新增 `reading_article_count` 列（迁移）；`punch_rules` 增加可选达标线 `readArticleMin`（默认 0 不强制，模式同 wordsMin）。

## 七、导入管线（5 个脚本，全部对齐现有脚本骨架：幂等 / 断点续传 / 失败清单）

```
[源站] --reading-fetch--> data/reading/raw/<source>/*.json   (快照+结构化, 血缘留档;
                             有音频源顺带下载原版整篇 mp3 → public/audio/reading/<id>/full.mp3)
        --reading-import--> 清洗(标点归一) → 分段 → 句切 → LLM 逐句翻译(编号回传+三重校验)
                             → 客观指标定级 → LLM 复核(CEFR/话题/摘要/glossary)
                             → 入库 readingArticles (幂等 by articleId)
        --reading-align---> faster-whisper 转写 full.mp3 → 句级时间戳 → 模糊匹配回句子
                             → 回写 timeline_json (对齐失败标记降级)
        --reading-tts-----> 无音频源补轨 B：段落合成 public/audio/reading/<articleId>/pNN.mp3
                             → 回写 paragraphs_json + audio_status
        --reading-check---> 质检: 轨A(full+timeline齐套) / 轨B(段落数=音频数) / 翻译句数校验
                             / 字段完整 / 等级·话题分布报表
```

| 脚本                           | 说明                                                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `scripts/reading-fetch.mjs`  | 多源抓取器，**源适配器**模式（`sources/bne`、`sources/newsinlevels`、`sources/dreamreader`…，各源独立解析函数 + 统一产物 JSON）；**有音频源顺带下载原版 mp3**（BNE 直链模式 `YYMM/<slug>.mp3` 已实测，NiL 从播放器 JS 取音频地址）；产物幂等跳过可续传；失败清单 `data/reading/failures.log` |
| `scripts/reading-import.mjs` | 清洗→句切→**LLM 逐句翻译（三重校验）**→定级→LLM 复核→入库；LLM 走 `src/lib/llm` 已有 provider，批量限速 + 失败重跑；等级/话题分布打印成人读报表                                                                                                                   |
| `scripts/reading-align.mjs`  | 轨 A 对齐：faster-whisper（本地 CPU）转写 full.mp3 → 句级时间戳 → 模糊匹配回句切结果 → `timeline_json` 回写；匹配率 <90% 标记降级                                                                                                                    |
| `scripts/reading-tts.mjs`    | 轨 B：照抄 `synth-audio-xdf.mjs` 骨架，**仅对无音频源补段落音频**；**修正 Python 路径为跨平台探测**（现脚本硬编码 macOS 路径，Windows 下用 `.workbuddy/binaries/python/envs/default` 或 `python -m edge_tts`）                                                |
| `scripts/reading-check.mjs`  | 齐套质检（轨 A：full+timeline；轨 B：段落数=音频数；翻译：句数校验）+ 统计报表（每级篇数/缺项清单/话题分布），入库验收的唯一口径                                                                                                                                        |

首批验收目标：**40–60 篇（每级 ≥10），音频齐套率 ≥99%，逐句翻译覆盖 100%，等级分布报表无空档**。

## 十、风险与对策

| 风险            | 对策                                                     |
| ------------- | ------------------------------------------------------ |
| 源站改版/反爬       | 适配器隔离（每源独立解析）；raw 快照留档保证旧素材可重导；限速与常规 UA                |
| VOA/BBC/维基不可达 | 首批不依赖；接口预留适配器位，代理可用即接入                                 |
| 轨 A 对齐失败      | whisper 模糊匹配容忍转写出入；匹配率 <90% 标记降级为整篇连播；后续可换 medium 模型重跑 |
| TTS 偶发失败      | 失败清单 + 重跑续传（现有管线已验证）；段落级粒度使单点失败影响最小化                   |
| LLM 逐句翻译错位/质量 | 编号回传 + 句数强校验 + 长度比报警 + 抽样审校 + 单句重翻；翻译失败不阻塞音频与阅读主流程     |
| 音频体积膨胀        | gitignore + 打包开关；轨 B 可重合成；磁盘紧张优先保留轨 A 原生音频             |
| LLM 定级/分类漂移   | 客观指标为一票，LLM 只做一档内修正 + 人工抽检 10% + 手动改级兜底                |
