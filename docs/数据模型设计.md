# 数据模型设计（v3.1 · 5 表方案）

> 版本：v3.1 · 2026-08-31
> 状态：已定稿（与用户逐条确认），待实施
> 取代：M1 的 12 表设计（`src/db/schema.ts` 旧版 + `docs/M1-实施计划.md` 中 Schema 章节）；
> v2 的 3 表方案 → v3 新增 `exam_sets`（套卷定义）→ v3.1 新增 `exam_sessions`（完整考试场次），
> 并将 `attempts` 更名 `exam_records`
> 配套决策：机考页面采用「托管 + 记录」复刻原型；M1 壳（启动链路 / 设置页 / config 双通道 / 心跳退出）保留

---

## 1. 为什么推翻 12 表

旧设计把**嵌套的富文本 DOM**（文章 + 题干 + 选项 + 填空位 + 表格 + 图片，天然长在一起）强行拆进
`papers → sections → passages → question_groups → questions → choices` 六张结构表，存在三个致命问题：

1. **拆的过程极难**：题目与内容深度嵌套，解析器复杂度爆炸且永远有漏网题型（听力表格填空为典型）；
2. **拼的过程必失真**：从结构表拼回页面，格式/图片/布局损失严重，效果远差于原型
   （原型效果好的根本原因恰是**直接渲染原始 HTML**）；
3. **对错题本与 AI 分析零增益**：分析需要的只是「题号、part、题型、对错、耗时」，
   不需要选项文本住在数据库里。

## 2. 核心原则

- **内容不入库**：真题 HTML / 图片 / 音频留在文件系统（`public/exams/<exam_id>/`），换皮产物零改造；
- **锚点即题目**：页面控件自带 `data-num` / `name="q-N"`，题号是 DOM、答案、作答三方的统一命名空间；
- **DB 只存数据**：套卷定义（exam_sets）+ 单科卷定义（papers）+ 考试场次（exam_sessions）
  + 单科考试记录（exam_records）+ 界面偏好（app_settings）；
- **判分复用已验证的 `scoring.js`**，仅新增：交卷后逐题结果 POST 回本地 API。

### 三层架构

```text
内容层（文件系统，不入库）
  public/exams/<exam_id>/
    ├─ reading.html / listening.html ...   ← 换皮产物，iframe 直接渲染，效果 = 原型 100%
    └─ exam-assets/…                       ← 原站 CSS/JS/图片/音频

数据层（SQLite，5 表）
  exam_sets · papers · exam_sessions · exam_records · app_settings

分析层（错题本 / AI 诊断）
  消费 exam_records.answer_sheet_json × papers.questions_json 聚合
```

## 3. 表结构

### 3.1 exam_sets — 套卷定义（1 行 = 一场完整考试的卷组）

| 字段 | 类型 | 说明 |
|---|---|---|
| exam_set_id | text PK | 套卷英文短标识，如 `a-2025jan`；导入幂等键 |
| title | text | 套卷显示名，如「A类 · 2025年1月真题 Test 1」 |
| category | text | `A`（学术类）/ `G`（培训类） |
| test_period | text | 考期，`"2025-01"` 格式，可排序可筛选 |
| created_at | timestamp | |

心智模型：**exam_sets = 一场考试的封面，papers = 封面里的三份单科卷，
exam_sessions = 一场完整考试的场次，exam_records = 考的历史**。
将来口语上线，加一行 speaking 卷（papers.subject = speaking）进同一套卷即可。
单科散卷（如只拿到某次阅读题）天然支持：建一个只含一份 papers 的 exam_set。

### 3.2 papers — 单科卷的静态定义（1 行 = 1 份单科卷）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | 自增主键 |
| exam_id | text UNIQUE | 卷的英文短标识（URL/目录名/幂等导入键），如 `a-2025jan-reading-test1` |
| exam_set_id | text FK→exam_sets | 属于哪套卷（必填） |
| subject | text | 科目：`reading` / `writing` / `listening`（预留 `speaking`） |
| title | text | 展示名，如「A类 阅读 · 2025 January Test 1」 |
| category | text | `A` / `G`，**冗余自 exam_sets**（见下方说明） |
| test_period | text | `"2025-01"`，**冗余自 exam_sets**（见下方说明） |
| duration_sec | int | 限时秒数（阅读/写作 3600，听力按源卷 data-time） |
| band_table_json | json | raw→band 换算表，`[[39,9],[37,8.5],...]` 降序，服务端算 band + 成绩页显示 |
| assets_json | json | 静态资源清单，见 §4.1 |
| questions_json | json | 题目档案（统计维度），见 §4.2；写作卷为 T1/T2 两条 |
| answers_json | json | 答案键（锚点 → 答案原串），见 §4.3；**写作卷无此列** |
| created_at / updated_at | timestamp | |

**为什么 title / category / test_period 在 papers 上冗余一份**：
单科卷列表页展示 papers 时若每次都要 join exam_sets，是本地单用户应用里自找的麻烦。
三个字段都是**只读快照**——导入时一次写入、永不更新，冗余的维护成本为零，
换来列表/筛选/详情全场景免 join。exam_sets 上保留同名列作为套卷视图的事实源。

**去重原则**：`max_score`、题型、锚点名只在 questions_json 存一份；answers_json 退化为纯值。

### 3.3 exam_sessions — 完整考试场次（1 行 = 一次完整考试）

一场完整考试（连考三科）有了自己的属性——开考/完成时间、总分、状态，独立成表。

| 字段 | 类型 | 说明 |
|---|---|---|
| session_id | text PK | 开考前生成，如 `a-2025jan-20260831-1830`（套卷id + 日期时间，人眼可读）；exam_records.session_id 指向它 |
| exam_set_id | text FK→exam_sets | 考的是哪套卷 |
| status | text | `IN_PROGRESS` / `COMPLETED` / `ABANDONED`（COMPLETED = 各科 exam_records 均有 band_score，含等写作 AI 批改到位） |
| started_at | timestamp | 第一科开考时间 |
| finished_at | timestamp | 最后一科出分时间（可空，完成时写入） |
| total_used_sec | int | 三科用时合计（最后一科完成时写入快照，列表展示免聚合） |
| overall_band | real | 总分快照：各科 band_score 平均、四舍五入到 0.5（雅思官方规则），完成时写入；与 band_score 同一"快照防漂移"原则 |
| created_at | timestamp | |

**单科练习不建场次**：exam_records.session_id 可空，散考就是散考，不产生只有一科的"假场次"。
"完整模考 vs 零散练习"的区分 = `session_id IS NULL` 一个条件。

### 3.4 exam_records — 单科考试记录（1 行 = 1 次单科考试，原 attempts 更名）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | 自增主键 |
| exam_id | text FK→papers.exam_id | 哪套卷 |
| subject | text | 冗余科目（列表页免 join） |
| session_id | text FK→exam_sessions，可空 | 属于哪场完整考试；单科随缘练习不填 |
| status | text | `IN_PROGRESS` / `SUBMITTED` / `COMPLETED` / `ABANDONED` |
| started_at | timestamp | 开考时间 |
| submitted_at | timestamp | 交卷时间（自动交卷同样写入） |
| used_sec | int | 实际用时 |
| correct_count | int | 答对题数（客观卷 0–40，判分的原始产物；写作卷为空） |
| band_score | real | 雅思成绩快照（考试时刻定格；客观卷由 band_table_json 换算，写作卷由 AI 四维综合） |
| answer_sheet_json | json | **答题卡**：考生作答 + 批改结果 + AI 元数据，见 §4.4 |
| created_at | timestamp | |

**correct_count 与 band_score 为什么两个字段都存**（band 本可由 correct_count + band_table 推导）：

1. **写作卷打破推导链**：band_score 有两个来源——客观卷走 band_table 换算，写作卷无
   correct_count、由 AI 四维综合。两字段独立可空，正好统一表达两种情况；
2. **快照防漂移**：换算表日后修订（听力 A/G 档位不同、官方新表）不应改变历史成绩，
   band_score 是"考试时刻判定的结果"定格，与 answer_sheet_json 的 part/type 快照同一原则；
3. **服务不同消费者**：correct_count 用于判分复核与错题核对，band_score 用于成绩条、
   趋势图与 AI 纵向对比（用户语境只说 band 不说 raw）。

### 3.5 app_settings — 界面偏好（k/v，不动）

非敏感界面设置。敏感配置（LLM apiKey / provider / endpoint / 端口）**不进 DB**，
继续走 M1 已有的 `config.json` 双通道（界面 ↔ 文件互认，mtime 优先）。

## 4. JSON 形状规范（列内契约）

### 4.1 papers.assets_json — 静态资源清单

```jsonc
{
  "entry": "/exams/a-2025jan/reading.html",      // 开考入口页（iframe 加载）
  "audio": "/exams/a-2025jan/listening.mp3",     // 听力卷才有
  "answersPage": "/exams/a-2025jan/answers.html" // 答案速查页（成绩页/错题本跳转用），没有则缺省
}
```

扩展性：新增资源类型（transcript、图片目录）直接加键，不改表结构。

### 4.2 papers.questions_json — 题目档案（键 = 题号）

```jsonc
{
  "23": { "part": 3, "type": "SINGLE", "anchor": "q-23", "max": 1 },
  "18": { "part": 2, "type": "BLOCK",  "anchor": "q-18-22", "max": 5 },
  // 写作卷：
  "T1": { "part": null, "type": "WRITING_TASK", "anchor": null, "max": null }
}
```

- `part`：阅读 Part 1–3 / 听力 Part 1–4；写作卷无 part
- `type`：`SINGLE` / `MULTI` / `FILL` / `TFNG` / `MATCH` / `BLOCK` / `WRITING_TASK`
  （由换皮脚本从源 HTML `data-q_type` 归一化产出）
- `max`：该题满分；普通题 1，块题 = 块内题数（按命中计分）
- 唯一使命：给作答数据补「part × 题型」分析维度

### 4.3 papers.answers_json — 答案键（键 = 锚点，纯值）

```jsonc
{ "q-1": "Keiko", "q-23": "D", "q-18-22": "A,B,C,F,G" }
```

- 存**官方答案原串**，不做任何加工（'/ ' 备选、'()' 可选段原样保留，展开是判分器的事）
- 块题整块一个答案集合
- 判分策略（kind）**不存储**，由 questions_json.type 确定性推导：

| type | 判分策略 |
|---|---|
| SINGLE / MULTI / TFNG / MATCH | 字母集合比对（setEq，排序后严格相等） |
| FILL / SHORT_ANSWER | 文本比对（textEq：小写化 + 按 `/` 拆备选 + 剥 `()` 可选段） |
| BLOCK | 按命中计分：\|用户选集 ∩ 正确集\|，每命中 1 分，上限 max |

- 来源：`prototype/exam-assets/answers-*.js` 的 `answers` 对象 + `blocks` 数组，脚本直导

### 4.4 exam_records.answer_sheet_json — 答题卡（作答 + 批改 + AI 元数据）

```jsonc
// 客观题条目（阅读/听力 40 条，未答的题也要有行：value=null, correct=false）
{ "number": 23, "part": 3, "type": "SINGLE", "value": "C", "correct": false, "points": 0 }

// 写作题条目（T1/T2）：考生全文 + AI 批改全信息（ai 子对象）
{ "task": "T1", "type": "WRITING_TASK", "value": "考生全文…",
  "correct": null, "points": null,
  "ai": { "status": "DONE", "model": "claude-sonnet-4", "tokens": 1850,
          "latencyMs": 8200, "retryCount": 0, "error": null, "gradedAt": "2026-08-31T17:40:00",
          "bands": { "TR": 6, "CC": 6, "LR": 5.5, "GRA": 6 }, "overall": 6 } }
```

- 键 = 锚点名（`q-23`）或任务号（`T1`），与页面锚点、answers_json 对齐
- part/type 为**作答时快照**：卷档案日后修订不影响历史分析
- 客观题条目无 `ai` 键；写作条目 `ai` 含模型名 / token 消耗 / 延迟 / 重试 / 报错 / 四维分，
  批改结果可复现有据可查

## 5. 数据流

```text
导入（离线，一次性）
  prototype/exam-assets/answers-*.js ──脚本──▶ exam_sets（1 行/考期）+ papers
  （papers.exam_id 幂等：已存在则跳过/覆盖；title/category/test_period 同步冗余到 papers）

开考
  仪表盘卷列表 ──点卷──▶ iframe 加载 assets_json.entry（换皮产物原样，效果 = 原型）
  完整套卷模式：选 exam_set → 创建 exam_sessions 1 行（生成 session_id）
  → 三科依次开考，各写 1 行 exam_records（session_id 指向该场次）

交卷
  scoring.js（判分 + band）──新增 ~30 行──▶ POST /api/exam-records
  服务端复核 correct_count / band_score（band_table_json 在 papers 上）──▶ 写入 exam_records 1 行
  三科均出分后：回写 exam_sessions（finished_at / total_used_sec / overall_band / COMPLETED）

回看 / 分析
  成绩页：读 exam_records + papers.questions_json
  错题本：answer_sheet_json 中 correct=false 的条目 → 跳回静态页锚点回看原题
  完整考试记录：读 exam_sessions（overall_band 等快照直接展示）
  AI 分析：exam_records 聚合（part × 题型正确率、趋势、弱项矩阵）→ LLM 生成诊断报告
```

## 6. 扩展与兜底

- **写作 AI 批改**：answer_sheet_json 条目内 `ai` 子对象，无独立表；批改异步进行，
  status 从 `PENDING → RUNNING → DONE/FAILED` 在条目内流转
- **若未来需要 SQL 级按题跨考试聚合**（当前规模下不需要）：一条脚本把
  answer_sheet_json 展开成独立 responses 表，数据无损，属可逆决策
- **旧 12 表处置**：`src/db/schema.ts` 重写，旧迁移文件删除重新生成；
  `attempts.responses / grading_results / questions / choices` 等表一并废弃，不保留兼容层

## 7. 实施清单（开工顺序）

1. 重写 `src/db/schema.ts`：12 表 → 5 表（exam_sets / papers / exam_sessions / exam_records / app_settings），重新生成迁移
2. 导入脚本：4 个 `answers-*.js` → exam_sets + papers（含 questions_json / answers_json / band_table_json，及 title/category/test_period 冗余快照）
3. 换皮产物拷入 `public/exams/<exam_id>/`
4. `scoring.js` 末尾新增交卷上报（POST /api/exam-records）
5. 新增 `/api/exam-sessions`（POST 创建场次 / GET 列表）与 `/api/exam-records`（POST 写入 / GET 列表）
6. 仪表盘改为「单科卷列表 + 完整套卷入口 + 考试记录」，点卷 iframe 开考；完整套卷模式创建 exam_sessions 场次，三科 exam_records 挂同一 session_id
7. 最小成绩页：从 answer_sheet_json 聚合对错矩阵（错题本与 AI 分析的地基）
