01

现状诊断：三个可量化的「生硬」根因

对 src/ 全量审计后的量化证据——「感觉生硬」不是玄学，是三个具体的工程缺口。

病灶一：颜色双轨制——主题无品牌色，色值散落硬编码

globals.css 的 shadcn 语义变量全部为无彩度灰（如 --primary: oklch(0.205 0 0)），没有品牌色；于是业务组件各自手写 hex 常量，形成「CSS 变量 + 硬编码」双轨并存。抽样自 plan/battle-home.tsx：

// 业务组件里手写样式常量，绕开了 ui/ 下的设计系统组件
const CARD  = "rounded-xl border border-[#dfe4ec] bg-white p-5";
const BTN   = "...bg-[#1a6feb]... hover:bg-[#0d4fa8]";
const HINT  = "text-xs text-[#8a93a2]";

硬编码色值分布（grep 全量统计）：

主蓝 #1a6feb×68 按钮/高亮
边框 #dfe4ec×40 卡片描边
弱文字 #8a93a2×39 提示文案
次文字 #5b6574×31 正文辅助
标题 #1c2330×16 深色文字
成功绿 ×2 值#18925c/#1a9e5c
警告橙 ×2 值#e8871e/#f0a03c

后果：想全局调一次品牌色要改 14 个文件；深浅色模式永远做不了；同一语义（如「成功」）存在多个近似值，视觉不一致。

病灶二：中文字体缺位——正文在用系统默认字

layout.tsx 只加载了 Geist({ subsets: ["latin"] })。页面声明 lang="zh-CN"，但中文字符全部回退到 OS 默认字体（各平台不一），字重层级、字距节奏都无法控制——这是「一眼生硬」最直接的来源之一。

病灶三：动效近乎为零——状态切换全靠「瞬移」

全项目仅 32 处 transition/animate（且多为 hover 变色）。弹窗直接弹出/关闭、列表无进出场、页面切换硬切、按钮点击无反馈、数字无滚动动画。交互「没有生命感」的本质是：所有状态变化都没有过渡。

同时确认的积极面 基础设施其实很齐全：shadcn CLI v4.19 已安装、@base-ui/react 1.7 原语已装、tw-animate-css 已引入、lucide-react / sonner / recharts 就位，.dark 主题变量已定义。缺的是「设计与动效层」，不是地基。
02

根因分析：为什么会变成这样

不是代码写得差，而是开发顺序的必然结果——先功能后视觉，缺一层「设计系统」中间层。

层级应有状态当前状态评级
基础设施层构建链、原语库、图标、toastNext 16 + Tailwind v4 + Base UI + lucide + sonner 全部就位优秀
设计系统层语义色板、字体栈、间距、圆角、组件变体语义变量全灰、无中文字体栈、业务绕开 ui/ 手写样式缺失
动效层进出场、微交互、页面过渡、数据动画无 motion 库，32 处零散 transition缺失
组件层业务组件基于设计系统组装14 个文件手写 hex 常量字符串割裂

核心结论：只要把「设计系统层 + 动效层」补上，再把业务组件渐进迁移过去，观感就会有质变——不需要推翻现有页面重写。

03

方案调研：四个维度的选型结论

围绕「组件系统 / 动效引擎 / 字体排版 / 灵感与效率工具」四条线完成调研（2026-09 最新生态）。

维度一 · 组件与主题系统：shadcn CLI v4（已装，直接用）

调研对象：shadcn/cli v4（2026.3）新能力、Radix vs Base UI 双轨
  • --preset 短码：一条命令打包切换整套设计系统（色板 + 主题 + 图标 + 字体 + 圆角），还支持 --dry-run / --diff 预检
  • --base base-ui：CLI 原生支持 Base UI 后端，与项目已装的 @base-ui/react 1.7 完全吻合
  • registry:font：字体成为一级安装类型，主题化时顺手解决字体
  • blocks 双版本：每个区块同时提供 Radix 与 Base UI 两版
  • 现有 ui/ 目录 7 个组件版本偏旧，需重新拉取对齐 v4
  • preset 色板是通用配色，品牌蓝 #1a6feb 需自定义主题（写进 CSS 变量即可）
结论：采用。项目已在 shadcn 生态内（CLI 已装、Base UI 已装），零迁移成本。第一步就是用 CLI 把主题 token 收敛 + 重装 ui/ 组件。

维度二 · 动效引擎：Motion（motion/react）为主 + CSS 原生为零成本补充

调研对象：Motion（原 Framer Motion 继任者）/ GSAP / CSS Scroll-Driven / View Transitions API
  • motion/react：~18KB，WAAPI 底层，声明式 spring 动画、AnimatePresence 进出场、layout FLIP、whileHover/whileTap —— React 生态事实标准
  • View Transitions API（Chrome 126+ / Safari 18+）：document.startViewTransition 一行代码做页面级过渡，Next.js App Router 可封装
  • Scroll-Driven Animations（animation-timeline: view()）：纯 CSS 滚动揭示，合成器线程执行，不阻塞 INP
  • framer-motion 包名已进入 legacy 维护模式，新项目一律用 motion/react
  • GSAP 仅复杂时间线编排有优势，本项目场景用不上，不引入
结论：动效决策树。装饰性/滚动动画 → 纯 CSS；React 状态变化、进出场、布局动画 → motion/react；复杂编排 → 不需要。所有动效必须尊重 prefers-reduced-motion。

维度三 · 中文字体与排版：思源黑体做正文基底

调研对象：思源黑体 / 阿里巴巴普惠体 / MiSans / HarmonyOS Sans / 霞鹜文楷
  • 思源黑体（Source Han Sans SC）：SIL OFL 免费商用，7 个字重，与 Noto Sans CJK 同源，webfont 生态支持最好
  • 备选：阿里巴巴普惠体 / MiSans / HarmonyOS Sans / OPPO Sans（均免费商用，风格略有差异）
  • 标题想要人文气质：霞鹜文楷（LXGW WenKai）做点缀
  • 字重纪律：正文 Regular · 按钮/小标题 Medium · 卡片标题 Bold · 大数字 Heavy
  • 排版黄金规则：正文 ≥16px（桌面）/ 14px（移动）、行高 1.5–2、单站 ≤3 种字体、对比度 ≥4.5:1（WCAG AA）
  • 实施：next/font 加载子集化 woff2，或 shadcn CLI 的 registry:font；务必声明完整中文字体栈兜底
结论：思源黑体为正文 + 同族字重分层。这是观感提升里性价比最高的一项：只改 layout.tsx + 字体栈，全站文字气质立刻统一。

维度四 · 灵感来源与效率工具：建立「抄袭」素材库

调研对象：Mobbin / react-bits / Magic UI / 21st.dev / v0 等（面向开发者的设计补给站）
  • Mobbin：1000+ 真实产品的完整用户流截图（2026 新增 AI 标签检索），学「正规军怎么做表单/弹窗/空态」
  • react-bits：100+ React 动效组件（文字效果/滚动动画/magnetic 按钮），可直接抄实现
  • Magic UI / Motion Primitives / Animate UI：基于 motion + Tailwind 的动效组件库，与 shadcn 同栈，copy-paste 即用
  • 21st.dev：「组件界的 GitHub」，AI 搜索 + shadcn 兼容复制
  • v0.dev：文字描述生成 shadcn + Tailwind 页面，适合出布局初稿再人工收敛
  • 颜色工具：用 OKLCH 空间从 #1a6feb 派生全套品牌色阶（60/30/10 法则：中性色 60%、品牌色 30%、强调色 10%）
结论：建立固定参考清单。遇到「这个控件该长什么样」就去 Mobbin 看成熟产品；要动效直接去 react-bits / Magic UI 抄同栈代码，不要自己发明。

推荐落地路线：四个阶段，每阶段独立可见

原则：先收敛再增强。每阶段结束都是「可发版」状态，按 P0→P3 命名沿用项目惯例。

STAGE P0
主题收敛
改动面：globals.css + 14 个组件文件
预期观感提升 ★★★☆☆
  • 确定品牌色板：以 #1a6feb 为锚，用 OKLCH 派生完整色阶，写入 globals.css 的 --primary / --background / --foreground / --muted / --border / --destructive 等语义变量顺手激活 .dark 变量（已定义未启用），dark 模式白送
  • 批量替换硬编码 hex → 语义类名（bg-[#1a6feb] → bg-primary 等），14 个文件机械替换 + 目测回归
  • 统一成功/警告/错误三组语义色（现在各有 2 个近似值），收敛为单一 token
  • 重新拉取 ui/ 下 7 个 shadcn 组件对齐 v4（button/card/dialog/input/label/select/sonner）
STAGE P1

  • 检查正文行高 1.6–1.75、段落间距、辅助文字对比度 ≥4.5:1
STAGE P2
动效注入
改动面：安装 motion + 各页面渐进接入
预期观感提升 ★★★★★
  • 安装 motion（motion/react），按决策树使用：状态/进出场用 Motion，装饰用 CSS
  • 高频交互点优先：弹窗/抽屉进出场（AnimatePresence）、按钮 whileTap 微缩、列表 stagger 进场、卡片 hover 浮起、成绩数字 count-up、骨架屏 shimmer
  • 页面切换：封装 View Transitions API（渐进增强，不支持的浏览器自动退回无动画）
  • 卷页 iframe 场景保持克制：机考页不加动效（还原真实考试环境），动效集中在仪表盘/记录/计划等工具页
  • 全局接入 prefers-reduced-motion 降级
STAGE P3
组件接管 + 趣味细节
改动面：持续、按页面滚动进行
预期观感提升 ★★★★☆
  • 新页面一律基于 ui/ 设计系统组件组装，不再手写样式常量；旧页面顺手迁移
  • 从 Magic UI / react-bits 挑选同栈组件增强：仪表盘空态插画、打卡日历连续打卡徽章动效、错题矩阵 hover 高亮行列
  • 遇到不确定的交互模式 → 查 Mobbin 对应 flow（onboarding/表单/空态/结果页）
  • 可选：用 v0 出布局初稿 → 人工收敛到设计系统
性价比排序（如果只做一件事） P0 主题收敛 + P1 字体升级合计约一天工作量，就能解决「生硬感」的大头（颜色杂乱 + 字体寒酸）；P2 动效是「有趣感」的主要来源，再花一到两天。不需要任何 UI 设计背景也能落地——所有决策都已收敛为 token 和规则。
