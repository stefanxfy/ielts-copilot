## 1. 设计原则（对齐 v3.1 全库哲学）

- **静态与动态一刀切**：words / word_books / book_word_relation 全是静态定义（导入写一次），学习状态独立成表
- **词全局唯一共享**：两本词书同含 abandon → words 只存一行内容，book_word_relation 各挂一条关联；进度全局一份且**跟词走不跟词书**（A 书学会 B 书自动认识，换书不重置）
- **内容不入库的例外**：音频 mp3 / 联想配图留文件系统（`public/audio/words/`、`public/images/words/`），库里只存路径——同「真题 HTML 不入库」惯例
- **JSON 列合并富信息**：释义/例句/词根等展示型内容合并 contentJson 一列，不生硬拆列；FSRS 记忆状态合并 fsrsState 一列（due 除外，见 §8）
- **不冗余衍生字段**：列表页词数 `count(book_word_relation)` 实时算；进度行数、今日复习数 `count(word_progress)` / `count(word_review_log)` 实时算

## 2. word_books — 词书定义（1 行 = 一本词书）

| 列 | 类型 | 约束 | 语义 |
|---|---|---|---|
| id | int | PK 自增 | |

## 4. book_word_relation — 关系表（1 行 = 某词书的第 N 个词）

| 列 | 类型 | 约束 | 语义 |
|---|---|---|---|
| bookId | int | FK → word_books.id **cascade** notNull | 删词书级联清关联（删词书重导是合法操作） |
| wordId | int | FK → words.id **restrict** notNull | 有词书引用的词条不许删（防误删共享内容） |
| order | int | notNull | 词在本书中的序号（0 起，词序即默认学习序） |
| | | **unique(bookId, wordId)** | 同词不重复入书 |
| | | **unique(bookId, order)** | 序号不撞（保序重排安全） |

> 索引：`index(bookId)`（取整本书按序读）、`index(wordId)`（查词被哪些书收录）。

## 5. contentJson 契约（words 富信息）

```ts
interface WordContent {
  /** 中文释义（多行，百词斩 mean_cn 拆 "；" ） */
  translation: string[];
  /** 英文释义（可空，百词斩 mean_en） */
  definition?: string[];
  /**
   * 例句。默认 1 条（来自百词斩 join），schema 支持多条无上限；
   * 字段：en 原句 / cn 中译 / audio 例句音频路径（可空）
   * 复习模式层用它做例句挖空（cloze），见 §11
   */
  examples: { en: string; cn?: string; audio?: string }[];
  /** 词根拆解（wordroot.txt，如 "port = carry → import/export/transport"） */
  root?: string;
  /** 词形变化（百词斩 sentence_phrase / ECDICT exchange 原串） */
  exchange?: string;
  /** 单词发音路径 /audio/words/abandon.mp3（文件在 public/audio/words/） */
  audio?: { word?: string };
  /** LLM 生成联想配图路径 /images/words/abandon.png（决策已立，管线后置；v1 先留位） */
  image?: string;
  /** 柯林斯星级 1–5（可空，ECDICT 补） */
  collins?: number;
  /** 考试标签 ["ielts","toefl"]（ECDICT tag 拆分） */
  tags?: string[];
  /** BNC 词频排名（数字越小越常用；可空，ECDICT 补） */
  bncRank?: number;
  /** 当代语料词频排名（数字越小越常用；可空，ECDICT 补） */
  frqRank?: number;
}
```

### 5.0 字段分类速查（用户视角）

| 字段 | 类型 | 来源 | 主要用途 |
|---|---|---|---|
| `translation` | string[] | 百词斩 mean_cn | 学习页/复习卡正面的中文释义；默写卡提示面 |
| `definition` | string[]? | 百词斩 mean_en | 高级模式展示英文释义、写作英解参考 |
| `examples` | {en,cn?,audio?}[] | 百词斩 sentence+sentence_trans | 学词展示语境；复习阶段例句挖空（cloze） |
| `root` | string? | ECDICT wordroot.txt 词根表 | 词根词缀法批量记词时展示 |
| `exchange` | string? | 百词斩 sentence_phrase / ECDICT exchange | 短语搭配、词形变化速查 |
| `audio.word` | string? | edge-tts 合成 | 学习页/复习卡点喇叭播放单词；默写卡读音提示 |
| `image` | string? | LLM 生图（后置） | 默写卡联想配图、认词卡记忆钩子 |
| `collins` | number? | ECDICT 1–5 星 | 学习中心标识「柯林斯星级」标签（高频权威性参考） |
| `tags` | string[]? | ECDICT 考试标签 | 词书分类筛选用（ielts/toefl/cet4…） |
| `bncRank` | number? | ECDICT bnc 排名 | 高频词排序：自学列表/默认学习序「先高频后低频」 |
| `frqRank` | number? | ECDICT frq 排名 | 当代词频排序，反映当前英语实际使用频率 |

**分组维度**：
- **展示型**（用户直接看到）：translation / definition / examples / root / exchange / audio.word / image
- **元数据型**（系统辅助）：collins / tags / bncRank / frqRank
- **承载型**（管线追溯）：examples[].audio 等子字段

> 字段命名沿用百词斩与 ECDICT 原 schema（mean_cn→translation、accent→phoneticUk、bnc/frq→bncRank/frqRank），保持上游解析层与落库字段一一对应，管线不用二次翻译。

## 6. 数据流（导入管线 → 三表）

```
素材管线产出 bundle（JSON）
  ├─ word_books         upsert（bookId 幂等）
  ├─ words              upsert（word 幂等；已存在则仅在内容为空时补全，不覆盖用户已有内容）
  ├─ book_word_relation delete+insert（按 bookId 整书重挂，order 重排）
  └─ edge-tts 异步任务  单词发音 mp3 落 public/audio/words/<word>.mp3，回写 words.contentJson.audio.word
```

**百词斩 join 步骤**（在 `applyWordBundle()` 内串行）：
```
1. ECDICT 拉词 + 落 words（contentJson 含 translation/definition/tags/collins/root）
2. 按 words 行去重,逐词 GET jsdelivr 百词斩单词 JSON（带超时+重试+失败跳过）
3. 命中: 取 sentence+sentence_trans 压一条入 examples;不命中: examples=[]
4. 调 edge-tts 合成单词音频(异步批量),落盘后回写 contentJson.audio.word
```

- **重复导入幂等**：同 bookId 再导 → 词书行更新、关联整组替换、词书内词集合变化正确反映
- **词不删**：关联 cascade 走掉，words 行残留无害（下次任何书用到自动复用）

## 8. word_progress — 学习进度表（v0.7 单轨定稿，1 行 = 一个词）

### 8.1 设计原则

- **进度跟词走，不跟词书**：words 全局唯一共享，记忆长在词上——表里没有 bookId，换词书、多词书不重置进度
- **单轨爬升，一词一行**：`UNIQUE(wordId)`。不设 dimension 双轨——会默写的词必然认识（产出包含识别，反向不成立），「先认后默、单向爬梯、出错跌落」认知上站得住，行数减半
- **体验合并、stage 决定题型**：用户只看到一个复习队列；出认词卡还是默写卡由 `stage` 字段决定——三种模式（认词卡/例句挖空/默写）是同一进度的不同侧重，不是独立功能
- **进度创建时机（用户拍板）**：**用户主动选词加入背诵计划时才 INSERT**，导入词书不预创建
- **静态 / 动态一刀切**：words 是内容定义（导入写一次），word_progress 是学习历史（每次复习都写）
- **删除级联兜底**：FK words.id cascade——删 words 行进度自动走掉（理论上 words 不该被删）

### 8.2 表结构

```ts
word_progress = {
  id:           int PK 自增,
  /** 进度与词 1:1 */
  wordId:       int unique notNull FK → words.id (cascade),
  /** 出题阶段:recognize 认词 | spell 默写。新词默认 recognize */
  stage:        text enum('recognize'|'spell') notNull default 'recognize',
  /** ACTIVE 在学 | IGNORED 用户跳过不再调度（可恢复） */
  status:       text enum('ACTIVE'|'IGNORED') notNull default 'ACTIVE',
  /** 下次到期时间 epoch ms——唯一高频查询条件，提升为列+索引 */
  due:          int notNull,
  /** FSRS 记忆状态 JSON：{ stability, difficulty, state, step }（ts-fsrs MemoryState 序列化） */
  fsrsState:    text json notNull,
  /** 累计答题次数 */
  reps:         int notNull default 0,
  /** 累计答错（跌落）次数 */
  lapses:       int notNull default 0,
  /** 最后评分时间 epoch ms */
  lastReviewAt: int,
  createdAt / updatedAt: int ts notNull default now,
}
索引: unique(wordId)
      index(status, due)   -- 到期复习队列查询（经典热点）
```

> **为什么只有 due 提列、其余收 JSON**：到期队列是唯一高频查询（`WHERE status='ACTIVE' AND due <= now`），必须有索引列；stability/difficulty/state/step 只在答题回写时读写，收进 `fsrsState` JSON 避免列爆炸。不存 lastRating 字段——评分效果已固化进 fsrsState + due，存了是职责重复。

### 8.3 FSRS-5 实现（ts-fsrs）

- **依赖**：`ts-fsrs`（FSRS-5 官方 TS 实现，开箱自带预训练默认参数，无需训练数据即可用）
- **评分映射**（UI 三键，Easy 不暴露）：

| 用户操作 | FSRS Rating | 数值 |
|---|---|---|
| 认识 | Good | 3 |
| 模糊 | Hard | 2 |
| 不认识 | Again | 1 |

- **答题回写**：`ts-fsrs.repeat(progress, now)` 得新 MemoryState + due → 更新该行 `fsrsState` / `due` / `stage`（按 §8.4 状态机）/ `reps` / `lapses` / `lastReviewAt`，同事务插一条 `word_review_log`
- **对 SM-2 的优势**（大词库多词书场景，用户已确认选型）：FSRS-5 三参数记忆模型拟合真实遗忘曲线，同样记住率下每日复习量比 SM-2 少约 25%；未来可用 word_review_log 积累的数据做参数优化（FSRS 招牌能力）

### 8.4 单轨状态机（用户定稿）

```
(无行) ──用户选词入计划──→ recognize (state=new, due=now)
recognize ──连续 2 次 Good──→ spell          （中间出现 Hard/Again 则连续计数清零重数）
recognize ──Hard/Again──→ recognize          （FSRS 正常缩短间隔，stage 不变）
spell ──默写全对──→ spell (Good，停留)
spell ──部分错误(编辑距离≤2)──→ recognize (Hard)
spell ──差距很大(编辑距离>2)──→ recognize (Again)
任意 ──用户标记──→ IGNORED（不出队列；可手动恢复 ACTIVE）
```

- **升级门槛 = 连续 2 次「认识」**（用户拍板）：第一次"认识"可能是蒙的，两次才上默写
- **降级深度按错误幅度**（用户定稿）："对"的判定仍严格二元（逐字母一致才算对，无部分得分），但错分两档跌落：部分错误降为「模糊」(Hard)，差距很大降为「不认识」(Again)——错也分错多深，不是容忍错误算对
- 降回 recognize 的词下次出认词卡，用户秒按"认识" → Good → 再升回 spell：看似浪费一张卡，实为记忆再巩固，代价可接受

### 8.5 默写判定规则（定稿）

```
提交时逐字母比对（输入过程可自由退格/移动光标修改，提交那一刻才判定）：
├─ 完全一致          → Good，停留 spell
├─ 编辑距离 ≤ 2      → Hard，stage 降回 recognize（"部分错误"，记得但手生）
└─ 编辑距离 > 2      → Again，stage 降回 recognize（"差距很大"，词形没记住）
```

- **编辑距离**（Levenshtein）：把错的改成正确拼写所需的最少单字符操作数（改/加/删一个字母各算 1）。相邻字母调换（recieve）在纯 Levenshtein 算 2，落进「模糊」区间，符合直觉
- 阈值 2 的依据：雅思核心词平均 8~10 字母，错 1~2 个字母通常是"记得但手生"，错 3 个以上基本是词形没记住
- 默写卡提示面（用户定稿）：**读音（自动播）+ 音标 + 中文释义 + 联想配图**（image 管线接上前无图不显示，互不阻塞）

## 9. word_review_log — 答题流水（只增不改不删）

| 列 | 类型 | 约束 | 语义 |
|---|---|---|---|
| id | int | PK 自增 | |
| progressId | int | FK → word_progress.id **cascade** notNull | |
| rating | int | notNull | FSRS 原生枚举 1~4（Again/Hard/Good/Easy），实际只出现 1~3 |
| stage | text | notNull | 答题时的 stage 快照（recognize/spell）——**历史事实，事后 join 不出来**（stage 会变），故落列 |
| reviewedAt | int | notNull | 答题时间 epoch ms |

索引：`index(progressId)`、`index(reviewedAt)`。

> 不冗余 wordId——经 progressId join 可得。用途：每日复习统计、易错词分析、未来 FSRS 参数优化（需要完整评分历史）。与 word_progress 更新同事务写入。

## 10. 复习模式层（体验合并、记录分开的实现）

**用户感知**：只有一条「今天该背的词」队列，三种出题方式按 stage 自动安排，无"模式切换"感知：

| stage | 出题方式 | 说明 |
|---|---|---|
| recognize | **认词卡** | 正面：单词 + 音标 + 读音；背面：释义 + 例句；三键评分 |
| spell | **默写卡** | 提示：读音 + 音标 + 中文释义 + 配图；键入拼写，§8.5 判定 |
| spell（变体） | **例句挖空卡** | 提示：例句挖去目标词 + 读音 + 配图；键入拼写，同 §8.5 判定。语境背单词（用户定稿）的复习形态，原料 contentJson.examples 零额外成本 |

- 默写卡与挖空卡的交替比例是 **session 层出题策略**（schema 不感知），v1 简单实现：每词首次 spell 复习出释义默写卡，之后与挖空卡交替；具体比例可后调
- **当日队列** = `word_progress WHERE status='ACTIVE' AND due<=now ORDER BY due`，一词一行天然混排；v1 全局队列，可选按词书过滤（join book_word_relation）
- **批次**：默认每日新词上限 20（可配），到期复习不限

## 11. 学习队列查询

```sql
-- 今日到期（复习 + 新词）
SELECT w.id, w.word, w.phoneticUk, w.contentJson,
       p.stage, p.due, p.fsrsState
FROM word_progress p
INNER JOIN words w ON w.id = p.word_id
WHERE p.status = 'ACTIVE'
  AND p.due <= :nowMs
ORDER BY p.due ASC
LIMIT :batchSize;

-- 可选按词书过滤：加 INNER JOIN book_word_relation r ON r.word_id = w.id
--               AND r.book_id = :bookId
```

要点：
- **不冗余计数**：今日复习数 `count(word_review_log where reviewedAt ∈ 今天)` 实时算
- **IGNORED 不出现在队列**：WHERE status='ACTIVE'
- **新词首日策略**：state=new 的词优先出认词卡（stage 本就是 recognize），与到期复习混排，新词限额单独计数
