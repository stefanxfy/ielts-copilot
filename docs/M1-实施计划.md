## 数据库 Schema（src/db/schema.ts）

### 四个关键决策

- **A · 富文本一律 HTML 片段列**（`stemHtml`/`bodyHtml`/`promptHtml`）：原型证明篇章/题干天然是 HTML（表格、句中填空、内嵌图）；渲染端 `dangerouslySetInnerHTML`（自入库受信数据；M2 解析器入库时可加一道标签白名单清洗作为加固项）。已与用户确认接受此方案（2026-08-30）。
- **B · 新增 `QuestionGroup` 题组表**（对 PRD §6 的最小扩展）：解决「多题共享选项集 + 部分计分」——A 卷 18-22 勾选块（5 题共享 A-H、按交集计分）、G 卷 Choose TWO、MATCH_* 共享 heading/字母列表。组上挂 `instructionHtml`、共享 Choice 集、`scoreMode`、`maxSelect`。
- **C · `Answer` 独立表**：开考接口只查 questions+choices，Answer 整表不下发 → 天然满足 PRD「不下发答案」。`explanation` 放 Answer 侧同理。
- **D · 答案语法原样移植不展开**：`Answer.value` 存官方原串（`'B'` / `'A,C'` / `'an agent/a registered agent'` / `'(heavy) import duties'` / `'TRUE'`），`'/'` 备选与 `'()'` 可选段的展开逻辑 = 原型 scoring.js 的 `textEq()/setEq()`，M3 原样移植为 `src/lib/scoring.ts`。块题计分修正：得分点数 = `maxSelect`，得分 = `min(|∩|, maxSelect)`。（2026-08-30 更新：原型早期「GT Q1 from==to 块声明」瑕疵已不存在——现行 answers 文件 Q1 为普通 `'A,C'` 文本答案；原型另验证了 **Q6 型 checkbox 双选单题**语义＝setEq 严格双对才得 1 分，M3 的 scoring.ts 需同时实现「单题双选严格匹配」与「块题按 maxSelect 命中计分」两种语义。）

### 表清单（核心列）

| 表 | 关键列 | 约束/索引 |
|---|---|---|
| `papers` | id, **slug**(幂等入库键), title, category('A'/'G'), **skill**(逗号列表 'READING','READING,WRITING'，M2 入库写入), source, status('DRAFT'/'PUBLISHED'), metaJson, 时间戳 | uq(slug); idx(status,skill) |
| `sections` | paperId, sectionNo, sectionType('READING'/'WRITING'), title, timeLimitSec(3600), orderIndex | uq(paperId,sectionNo) |
| `passages` | sectionId, orderIndex, title, subtitle, **bodyHtml**, imageUrl（图片型篇章，如 GT S1） | idx(sectionId,orderIndex) |
| `question_groups` | sectionId, instructionHtml, layoutHint, **scoreMode**('PER_QUESTION'/'SET_INTERSECTION'), minSelect/maxSelect, orderIndex | idx(sectionId,orderIndex) |
| `questions` | paperId(冗余，供 uq(paperId,number)), sectionId, groupId, **number**(1-40 全卷连续), **type**(PRD §3.3.3 九值枚举), stemHtml, instructionHtml, wordLimitJson, passageOrder, taskId(PRD 预留), metaJson | uq(paperId,number); idx(section)/(group)/(type) |
| `choices` | questionId XOR groupId（CHECK 二选一）, label, textHtml, orderIndex | idx(question)/(group) |
| `answers` | questionId, **value**(官方原串), alternativesJson, explanationHtml | uq(questionId)；永不出现在开考 payload |
| `attempts` | paperId(restrict), status('IN_PROGRESS'→'SUBMITTED'→'COMPLETED'/'GRADING'/'ABANDONED'，M1 只建列), startedAt/submittedAt/completedAt, usedSec, rawScore, bandScore, correct/wrong/blankCount(冗余), highlightsJson(列先留，结构 M3 定) | idx(paperId,startedAt)/(status) |
| `responses` | attemptId, questionId XOR writingTaskId（CHECK）， **valueJson**(统一 JSON，见下), isMarked(Review 标记), isCorrect/points(判分回填), updatedAt | uq(attemptId,questionId)；uq(attemptId,writingTaskId) |
| `writing_tasks` | paperId, taskId('T1'/'T2'), promptHtml, materialHtml(GT 书信情景), wordMin, suggestedTimeSec, orderIndex | uq(paperId,taskId) |
| `grading_results` | attemptId, writingTaskId, status('PENDING'/'RUNNING'/'DONE'/'FAILED'), resultJson, rawJson, model 快照, error, latencyMs, tokens, retryCount | uq(attemptId,writingTaskId) |
| `app_settings` | key PK, valueJson, updatedAt | |

写作作答挂 `writingTaskId` 显式外键（对 PRD §6 `Question.taskId` 隐式对齐的精化，`Question.taskId` 列保留为预留位）。band 换算表不建表 → `src/lib/band-table.ts` 常量。

### 图片存储（2026-08-30 与用户确认）

**图片不进 SQLite，存文件系统 `public/exam-assets/<卷slug>/`（每卷一子目录防冲突），DB 只存引用路径**，Next 静态服务直出。三种形态：正文内嵌图 → `bodyHtml` 内 `<img src="/exam-assets/<slug>/…">`；整篇图片型篇章（GT 卷 S1）→ `passages.imageUrl`；题目/写作材料图 → 内嵌 `stemHtml`/`materialHtml`。M2 解析器负责拷图 + 重写 `src`，并**校验每个引用都有对应文件**（缺文件拒入库）。不选 BLOB 的理由：PRD V3「导出仅含结构化数据与引用路径」即文件引用设计；BLOB 膨胀 DB、需服务路由、单文件备份优势对「文件夹即应用」形态无意义。postbuild 拷 `public/` 进 standalone 产物保证打包可用。

### Response.valueJson 形态（统一 JSON 单列）

| 题型 | 形态 |
|---|---|
| 单选/TFNG/MATCH_*（下拉） | `"B"` / `"TRUE"` / `"F"` |
| MULTI_CHOICE | `["A","C"]` |
| SET_INTERSECTION 块 | 数组写入块内每题（同值），判分组级去重；换取题号板/回放逻辑均匀 |
| FILL_BLANK / SHORT_ANSWER | `"biggest"` |

**作答与题目的对应 = `responses(attemptId, questionId)` 外键对**（uq 索引保证一考一题一行，暂存幂等）；句中填空的空位在 M2 解析时转为 stemHtml 内的 `<span data-qnum="N"></span>` 标记，M3 渲染层据此挂受控输入框 —— 数据层对应始终是外键，不靠 DOM 位置或文本匹配。判分 `responses JOIN answers ON questionId`，回放 `questions LEFT JOIN responses ON (paperId, attemptId)`。
| 写作 essay | 全文（不判分，走 GradingResult） |

### 迁移策略

`drizzle.config.ts`(sqlite, out=./src/db/migrations) → 开发期 `db:generate`，**migrations 进 git**；运行时 `instrumentation.ts` 的 `register()` 自动 `ensureDataDir` → 连接 → `migrate()`（drizzle journal 幂等，dev/standalone 双态都执行）；migrations 目录解析：env `IELTS_APP_ROOT` 覆盖 → `<root>/src/db/migrations`(dev) → `<root>/next-server/drizzle-migrations`(postbuild 拷贝)。

## config.json 模块

- **读**：strip-json-comments 去注释 + 尾逗号容错 → zod 校验（字段级报错不崩溃）→ mtime 缓存（`statSync` 每次核对，满足 PRD §11-4「以文件 mtime 为准」）。
- **写**：tmp 文件 + `renameSync` 原子写；重新生成固定注释版式（不做用户自定义注释 AST 保留——README 写明，`config.example.json` 承载完整文档）。
- **校验规则**：host 白名单只允许 `127.0.0.1|localhost|::1`（PRD §7 强制面）；port 1-65535；provider 三值枚举；timeoutSec 5-600。
- **GET /api/config**：永不下发完整 apiKey，返回 `apiKeyMasked`(前4+…+后4) + `apiKeySet` + `fileMtime`。
- **PUT /api/config**：body 缺省/空 apiKey = 保持现值；带 `baseMtime` 乐观并发，不匹配返回 **409** + 最新脱敏配置 → 设置页「已被外部修改，一键重载」。
- **POST /api/config/test-llm**：**原生 fetch 直连，不用 SDK**（V1 每 provider 只碰 1 端点，控依赖体积）。openai → `POST {baseUrl}/chat/completions`(`max_completion_tokens`)；openai-compatible → 同端点(`max_tokens`)；anthropic → `POST {baseUrl}/v1/messages`(`x-api-key`+`anthropic-version`)。超时 `min(timeoutSec,30)s`；错误分类 AUTH/NOT_FOUND/RATE_LIMIT/TIMEOUT/NETWORK/HTTP，设置页出人话提示。

## 启动脚本

**「浏览器关闭 = 退出」机制（跨平台统一）**：heartbeat.tsx 每 5s POST `/api/heartbeat`（visibilitychange 回前台补发）→ 服务端模块级 `lastBeat` → 看门狗（仅打包模式，env `IELTS_HEARTBEAT_EXIT=1` 开启；`next dev` 不开防误杀）每 10s 检查，`>90s` 二次确认后 `process.exit(0)`（90s > Chrome 后台标签 ≥60s 节流）。

**启动.command**（bash）：`cd "$(dirname $0)"` → 查 node（缺/主版本<22 → open docs/need-node.html）→ 无 `next-server/server.js` 时兜底 `npm install && npm run build` → 读 config 端口（node -e 容注释）→ `lsof` 占用则 +1 递增（上限 +20，只进临时变量不写回 config）→ `HOSTNAME=127.0.0.1 PORT=$PORT IELTS_HEARTBEAT_EXIT=1 node next-server/server.js &` → `curl /api/health` 轮询（60s 超时）→ `open` 浏览器 → `wait $PID`。

**启动.bat**（cmd）：**2026-08-30 用户决定 M1 先不做，移至 M5。** 原设计（M5 实施参考）：同构；端口检测用 PowerShell `Get-NetTCPConnection`；健康后开浏览器用后台 powershell；node 前台运行（关 cmd 窗口经 CTRL_CLOSE_EVENT 带走 node）。逐行注释文档化假设，标注「M5 实测」。

**postbuild.mjs**（build 自动跑）：`rm -rf next-server` → 拷 `.next/standalone` → 拷 migrations 到 `next-server/drizzle-migrations` → **强制补拷 better-sqlite3 整目录**（tracing 偶发漏 `.node`）→ 拷 `public` 与 `.next/static`（M2 真题图片靠这步进包）。

**dev 与双击共存**：同目录双态；开发 `npm run dev`（无心跳退出）；`.gitignore`：`node_modules/ .next/ next-server/ data/ config.json`（`data/.gitkeep`、`config.example.json` 进库）。

## 风险与对策

1. **better-sqlite3 × Next 打包**（最高风险）：serverExternalPackages 必配；standalone tracing 漏拷 `.node` 由 postbuild 强制补拷兜底；**ABI 绑定**（本机 Node 24 → 产物绑 ABI 137）→ 启动脚本版本闸 ≥22 + README 标注 + M5 便携 Node 锁版本。步骤 6 验收须在干净产物目录实测。
2. **Next 16 变化**：动态路由 params 是 Promise（M2 API 一开始就 await）；Turbopack 异常时兜底 `next build --webpack`。
3. **JSONC 写回丢用户注释**：固定版式重生成 + example 文件 + 409 机制；README 写明。
4. **Windows .bat**：2026-08-30 决定 M1 整项不做，M5 连脚本编写带真机验证一起做（心跳退出机制跨平台统一，.bat 只剩进程编排差异，延后无架构风险）。
5. **心跳误杀**：阈值 90s+二次确认；dev 模式 env 开关隔离。
6. **SQLite 细节**：better-sqlite3 默认不开 FK（必须 pragma）；WAL 伴随文件已被 gitignore data/ 覆盖。
