## 2. 新增数据表（P1 共 2 张：成绩流水 + 中途进度）

### 2.1 `typing_sessions`：跟打成绩流水

```ts
export const TYPING_MODES = ["article", "drill"] as const;

/** errorCharsJson 单条 —— 最终错字明细（只记最终文本错误，中途改对不算错） */
export interface TypingError {
  /** 错字在全文中的位置（0 起） */
  pos: number;
  /** 应打字符 */
  expected: string;
}

/** drillMetaJson —— 重练稿生成元信息（drill 模式专用） */
export interface TypingDrillMeta {
  /** 触发本次重练的高频错词 */
  triggerWords: string[];
}

export const typingSessions = sqliteTable("typing_sessions", {
  id: int("id").primaryKey({ autoIncrement: true }),
  /** article=整篇跟打 / drill=错词重练生成稿 */
  mode: text("mode", { enum: TYPING_MODES }).notNull().default("article"),
  /** 来源文章幂等键（reading_articles.article_id）；drill 为 NULL。
   *  不设外键——文章删除后历史记录保留、查看时跳过（v1.2 用户拍板：不存正文快照） */
  articleId: text("article_id"),
  /** 用时（秒） */
  durationSec: int("duration_sec").notNull(),
  /** 全文总字符数 */
  charTotal: int("char_total").notNull(),
  /** 最终正确字符数 */
  charCorrect: int("char_correct").notNull(),
  /** 退格次数（键位不熟的诊断指标） */
  backspaces: int("backspaces").notNull().default(0),
  /** 最高连击：连续输入正确字符的最大数（复盘面板指标卡用） */
  maxCombo: int("max_combo").notNull().default(0),
  /** 净速度：(charCorrect / 5) / (durationSec / 60)，服务端计算 */
  wpm: real("wpm").notNull(),
  /** 最终准确率：charCorrect / charTotal，服务端计算 */
  accuracy: real("accuracy").notNull(),
  /** 最终错字明细（错键热力 / 错词清单的原料；全对为 NULL） */
  errorCharsJson: text("error_chars_json", { mode: "json" })
    .$type<TypingError[]>(),
  /** drill 生成元信息（article 模式为 NULL） */
  drillMetaJson: text("drill_meta_json", { mode: "json" })
    .$type<TypingDrillMeta>(),
  startedAt: int("started_at", { mode: "timestamp" })
    .notNull()
    .default(sql`(unixepoch())`),
}, (t) => [
  index("idx_typing_sessions_started_at").on(t.startedAt),
  index("idx_typing_sessions_article").on(t.articleId),
]);
```

**字段清单（`typing_sessions`）**：

| 字段 | 列名 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|---|
| id | `id` | INTEGER | **PRIMARY KEY**，autoincrement | 自增主键 |
| mode | `mode` | TEXT | NOT NULL，enum | `article`=整篇跟打 / `drill`=错词重练稿 |
| articleId | `article_id` | TEXT | 可空 | 来源文章幂等键；drill 为 NULL；不设外键（删文后记录保留、查看跳过） |
| durationSec | `duration_sec` | INTEGER | NOT NULL | 用时（秒） |
| charTotal | `char_total` | INTEGER | NOT NULL | 全文总字符数 |
| charCorrect | `char_correct` | INTEGER | NOT NULL | 最终正确字符数 |
| backspaces | `backspaces` | INTEGER | NOT NULL，default 0 | 退格次数 |
| maxCombo | `max_combo` | INTEGER | NOT NULL，default 0 | 最高连击（连续正确字符最大数） |
| wpm | `wpm` | REAL | NOT NULL | 净速度，服务端算（防篡改、口径统一） |
| accuracy | `accuracy` | REAL | NOT NULL | 最终准确率，服务端算 |
| errorCharsJson | `error_chars_json` | TEXT (json) | 可空 | 最终错字 `[{pos, expected, word?}]`（v1.3：`word` = 错字所在小写单词，article 模式服务端从原文回填，是**无 textSnapshot 后错词聚合的唯一原料**） |
| drillMetaJson | `drill_meta_json` | TEXT (json) | 可空 | drill 触发词 |
| startedAt | `started_at` | INTEGER (timestamp) | NOT NULL，default `unixepoch()` | 开始时间（趋势曲线横轴） |

索引：`idx_typing_sessions_started (started_at)`、`idx_typing_sessions_article (article_id)`。

**设计决策**：

- **为什么聚合不预建表**：错词清单 / 错键热力都能从 `errorCharsJson` 在查询时聚合（expected → 字符频次；word → 词频），数据量小（一天几十条），**不预建聚合表**——先简后繁，聚合慢了再物化。
- **为什么不存 `textSnapshot`（v1.2）**：用户拍板——文章删除后打字记录**跳过**即可，不为此冗余存储全文；`articleId` 存在时可回溯源文章正文，drill 稿为一次性生成物不留存。代价是错字的**词级信息必须在打分时落库**，故 v1.3 给 `TypingError` 补 `word` 字段。
- **为什么 wpm/accuracy 服务端算**：口径唯一，前端只传原始击键数据。
- **同一篇文章可反复练**：不设唯一约束，重复练习是需求（提熟）；文章卡「最佳成绩」取该文 wpm 最高一条。

### 2.2 `typing_progress`：跟打中途进度（v1.3 新增，1 行 = 一篇在打的文章）

「进入即打 + 进度可恢复」需求（用户 2026-09-12 明确：刷新不丢、重启不丢更好）的状态表。**upsert 覆盖写**，不是流水——打字中 2s 防抖上报，永远只有一篇文章一行，打完整篇提交 sessions 时删除。

```ts
export const typingProgress = sqliteTable("typing_progress", {
  /** PK + FK CASCADE:删文章级联清中途进度 */
  articleId: text("article_id")
    .primaryKey()
    .references(() => readingArticles.articleId, { onDelete: "cascade" }),
  /** 已打到的字符位置（0 起，续打定位） */
  pos: int("pos").notNull().default(0),
  /** 打错字符位置数组（稀疏——只存错的，"对"是默认值不落库） */
  errorPosJson: text("error_pos_json", { mode: "json" })
    .$type<number[]>()
    .notNull()
    .default(sql`(json_array())`),
  startedAt: int("started_at", { mode: "timestamp" }).notNull().default(sql`(unixepoch())`),
  updatedAt: int("updated_at", { mode: "timestamp" }).notNull().default(sql`(unixepoch())`),
});
```

| 字段 | 列名 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|---|
| articleId | `article_id` | TEXT | **PRIMARY KEY**，FK → reading_articles CASCADE | 一篇文章一行；删文清档 |
| pos | `pos` | INTEGER | NOT NULL，default 0 | 已打字符数（续打定位） |
| errorPosJson | `error_pos_json` | TEXT (json) | NOT NULL，default `[]` | 错字位置稀疏数组；恢复时 marks[pos]=false，其余已打视为对 |
| startedAt / updatedAt | `started_at` / `updated_at` | INTEGER (timestamp) | NOT NULL | 本篇开始 / 最后保存时间 |

**进度持久化口径**：打字中 **2s 防抖 PUT**；`visibilitychange`（切后台）与 `pagehide`（刷新/关页，`keepalive: true`）兜底上报；**ESC = 存档暂停**（提示可随时回来续打）；**重置按钮 = DELETE 清档重打**；打完整篇 → sessions 入库 → 服务端删该文进度行。恢复时**用时从续打首键重新计时**（存档前段不计入本次 durationSec）。换机同步走 app.db git 流。

## 3. 统计口径（必须严谨，一处定义）

| 指标 | 定义 | 说明 |
|---|---|---|
| **WPM（净速度）** | `(charCorrect / 5) / (durationSec / 60)` | 打字行业标准口径：1 word = 5 chars（含空格）；只按最终正确字符计 |
| **准确率** | `charCorrect / charTotal` | **最终准确率**——只看打完后的全文，中途打错又改对不扣（机考评分看最终文本，不看过程） |
| **退格数** | `backspaces` | 诊断指标：退格多 = 键位不熟，不直接进速度/准确率 |
| **最高连击** | `maxCombo` = 连续输入正确字符的最大数 | 复盘面板指标卡；累计视角取 `MAX(max_combo)` |
| **文章完成** | 打完全文最后一个字符并提交 | 中途退出**不入库**（避免脏数据；刷新=放弃）；整篇较长，是否支持中途续打见 §9 |

不引入「毛速度 / 净速度双显示」「击键级准确率」等复杂口径——机考场景只关心**最终文本又快又对**。

## 4. 跟打器交互（文章跟打，P1 主功能）

### 4.1 入口与流程

- 路由 `/typing`（阅读库地基文档预留），顶部导航「打字练习」入口。
- 流程两层（v1.2）：**选文章**（复用 `GET /api/reading` 列表数据，零新建接口，卡片显示文章级最佳成绩）→ **直接进入整篇跟打器**，段落清单页取消。
- 阅读学习页段落 ⋯ 菜单「送入打字练习」（阅读库原型已预留）直达**该文章**跟打器。

### 4.2 跟打区三态渲染

- **未到**：灰色；**已打对**：正常前景色；**打错**：红字浅红底。
- **打错即时标红但不阻塞输入**——允许继续往下敲（机考真实感受），段落结束时统一统计最终错误。
- 当前待打字符用底色块 + 细边框高亮；跟打区视口自动跟随光标滚动。
- **整篇渲染（v1.2）**：全文按段落分块显示（段间空行分隔），**输入流跨段连续**——段尾字符打完光标自动衔接下一段首，**无需敲回车**（回车留待写作仿真，跟打阅读稿不引入无意义击键）。
- 段内顶部常驻实时条：**计时 · 实时 WPM · 退格数**（三件套，够用即可）。
- 完成一段 → **错误复盘面板**（§4.4，当次视角）→ 「下一段」按钮。

### 4.3 退格与输入策略

- **自由退格**，不做竞速锁定——机考允许编辑修改；退格次数单独记录。
- 键盘输入捕获：跟打区 focus + `keydown` 直捕；**屏蔽 IME**——监听 `compositionstart`，检测到中文输入法组合态立即提示「请切换到英文输入法」（机考场景就是纯英文键盘）。
- `Tab` 不参与（跳下一题是机考答题卡行为，跟打场景禁用避免误触失焦）。

### 4.4 错误复盘面板（v1.1 新增，参考用户截图）

打完一段（以及统计页的累计视角）共用的复盘组件 `TypingReview`，props = 数据源（当次 session / 累计聚合），一次开发两处复用。布局自上而下：

1. **视角切换**：「当次 / 累计」两个 tab——当次 = 本段成绩；累计 = 全部 session 聚合。
2. **四指标卡**：最终 WPM · 准确率 · 总错误数 · 最高连击（累计视角：WPM 取近 10 段均值、错误数求和、连击取 MAX）。
3. **最易出错字母 TOP 8**（左列）：字母块 + 打错次数 + 占错误比——数据源 `errorCharsJson` 聚合（expected 频次）。
4. **键盘错误热力图**（右列）：QWERTY 三排布局（`qwertyuiop / asdfghjkl / zxcvbnm`），错误字符按频次分三档红色阶——**少量**（1 次 `#F7C1C1`）/ **中等**（2–3 次 `#F09595`）/ **高频**（≥4 次 `#E24B4A`），无错误键白底；底部三档图例。数据源与 TOP 8 同源，纯前端渲染零新接口。
5. **错词清单**（当次视角附加）：本段最终打错的单词，命中词库的显示「查看释义」入口（复用 `/api/words/lookup` 词卡）。

- 累计视角数据源：`/api/typing/stats` 返回 `keyFreq`（`{char: count}`）供 TOP 表与热力图，无需前端全量拉流水。
- 设计意图：热力图回答「**哪个键在手上看不见、在数据里看得见**」——例如 `th` 常打成 `ht`、右手小指够 `p` 慢半拍，直接指导键位专项；与 §5 错词重练闭环共用同一份聚合原料。

## 5. 错词重练闭环（P1 同期）

数据流：

```
sessions.errorCharsJson + textSnapshot
  → 聚合服务 lib/typing/aggregate.ts
     · 词级：pos 映射回所在单词 → 高频错词清单（Top N）
     · 字符级：expected 频次 → 错键清单（th / ie / 双写…）
  → drill 生成器：从已有阅读库段落检索含高频错词/错键组合的句子
     · 检索到 → 句子序列拼接为 drill 稿（drillMetaJson 记触发词；稿为一次性生成物不留存）
     · 检索不到 → 回落：错词本身拼成词序列（纯词表打）
  → GET /api/typing/drills → mode=drill 的 session 照常入库
```

- 入口：`/typing` 页顶部「错词重练」卡——显示高频错词数与 Top 5 错词，「开始重练」按钮。
- 错词闭环复用词卡：重练小结中错词仍命中词库的继续给释义入口。
- 高频阈值先用「出现 ≥2 次」的词取 Top 20，跑起来再调。

## 6. API 设计（v1.3 实施定稿：4 个新接口 + 1 复用）

| 接口 | 方法 | 职责（✅ = 已实现） |
|---|---|---|
| `/api/typing/sessions` | POST ✅ | 提交一次成绩。article 模式：服务端按 articleId 用同一 norm 口径从 `paragraphsJson` 拼全文**校验 charTotal**，客户端只传 `errorPos` 位置数组，服务端逐位回填 expected/word → `errorCharsJson`；drill 模式：信任客户端 `errorChars`。**服务端计算 wpm/accuracy**；成功后**删除该文 typing_progress** |
| `/api/typing/progress` | GET / PUT / DELETE ✅ | 中途进度：GET `?articleId=` 恢复；PUT upsert（2s 防抖 + keepalive 兜底）；DELETE 显式清档（重置场景） |
| `/api/typing/stats` | GET ✅ | 累计汇总：场数/平均 WPM/平均准确率/累计错误数/最高连击/**错键频次 keyFreq**（复盘面板累计视角数据源；趋势曲线 T2 再扩） |
| `/api/typing/drills` | GET ✅ | 聚合 article 模式 `errorChars[].word` 高频错词 TOP5 → 阅读库句子检索（含触发词，按命中数降序，凑 ~520 字符）拼重练稿；检索不到回落词序列稿；无错词积累返回 `{triggerWords:[], text:null}` |
| `/api/reading`(+`/[articleId]`) | GET（复用） | 跟打选文章列表与全文，零新建 |

文本归一口径：`src/lib/typing/text.ts` 的 `normTypingText`（弯引号→直引号、em/en dash→`-`、NBSP→空格）**客户端与服务端共用**，保证拼接长度校验与字符比对两边一致。

## 7. 写作仿真（独立功能，后期，本期零建表）

> 用户定稿：写作仿真**单独成功能**，排在打字练习之后；核心 = 抽写作真题要求、**无限练习**。

- **素材可行性（2026-09-11 已实测）**：`papers` 表 writing 卷 **146 套，100% 含结构化题干**——`public/exams/<examId>/writing.html` 中 `section.test-contents` + `h1.test-contents__title`（"Writing Task 1/2"），下方 `<p>` 依次为任务说明（"You should spend about 40 minutes…"）、题干（`p.Indent1`，可能多段/含列表）、字数要求（"at least 250 words"）。A 类 Task 1 配图（chart）在 section 内 `<img>`；G 类 Task 1 书信为纯文本题干。
- **届时新建表 `writing_prompts`**：examId / taskNo / taskType（A/G）/ promptText / minWords / imageUrl / sourceRefJson；解析脚本对齐 `reading-import-paper.mjs` 惯例（幂等 / 断点续传 / 失败清单）。

## 10. 键音规格（v1.3，§4.5）

Web Audio API 实时合成，**零音频文件**；首次 keydown 惰性创建 AudioContext（浏览器自动播放策略要求用户手势，天然满足）。正确/错误两音分离，错误音刻意低沉刺耳（闭眼可感知）。偏好存 localStorage `typing-sound`，选择器切换即试听。

| 方案 | 正确音 | 错误音 |
|---|---|---|
| `mech` 机械键盘（默认） | 青轴噪声脉冲（带通 2.8–3.6kHz 随机，每键微变） | 150→90Hz 方波低鸣 |
| `thock` 静电容「碎碎」 | 低频带通噪声 500–650Hz + 短正弦衬底 | 锯齿波 110→70Hz |
| `tick` 轻快滴答 | 正弦 1250→900Hz 短嗒 | 双声嘟嘟 |
| `type` 打字机 | 噪声 1.4kHz + 泛音嗒哒 | 三角波「叮」铃 1560→1150Hz |
| `piano` 钢琴音阶 | 每键随机 C 大调五声音阶 + 高八度泛音 | 小二度不协和双音（196/207Hz） |
| `jelly` 果冻泡泡 | 上滑「啵」420→760Hz | 低频双咚 |
| `off` | 静音 | 静音 |

正式实现已在 `/typing` 落地（`src/app/(shell)/typing/page.tsx` 内联引擎）；若后续要**真实键盘 wav 采样**，走外置素材路线（同接口替换实现即可）。
