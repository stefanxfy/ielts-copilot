# 阅读功能实施计划（建表 → 真题导入 → 前后端）

> 版本：v1.0 · 2026-09-10
> 修订：v1.0 初稿
> 定位：`阅读库数据模型与交互设计.md` v1.4 的**执行排期**——按「先建表 → 导入真题（纯文本清洗，本期不含音频）→ 前后端实现」三段推进。
> 依据（2026-09-10 实测）：真题正文在 `public/exams/<examId>/reading.html`，每份含 **3 个 `field--name-field-passage` 容器**（= P1/P2/P3），段落以 `<p>` 平铺，段内混有空 `<strong></strong>` 标记噪声；`field-passage-desc` 存文章标题；`Part 1/2/3` 标题与容器一一对应。现有数据：`a-2025jan-reading-test1`、`gt-vol1-reading-test1` 两份。

---

## 阶段 P1：建表（0.5 天）

**产出**：3 张新表入 `src/db/schema.ts` + drizzle 迁移。

1. `schema.ts` 追加 `readingLibraries` / `readingArticles` / `readingProgress` 三表与 `ReadingSourceRef`、`ReadingParagraph`、`READING_*` 枚举类型（照抄设计文档 §2 的 TS 定义）。
2. 导出 JSON 契约类型（`ParagraphsJson` 等），供前端 `import type` 使用——沿用现行 schema 导出惯例。
3. 迁移：`npx drizzle-kit generate` → `npx drizzle-kit migrate`；迁移文件入库。
4. 种子：不预置库——首次导入时脚本 upsert 预置库 `past-paper`（source=builtin）。

**完成判据**：迁移零错误；三表在 SQLite 中可空表读写；`reading_articles.library_id` 外键 RESTRICT 生效（空库可删、非空库删除被拒）。

## 阶段 P2：真题清洗导入（1–1.5 天）

**产出**：`scripts/reading-import-paper.mjs`，把 `papers`（subject=reading）对应的 reading.html 解析为纯文本段落入库。

**清洗规则（只需要纯文本）**：

| # | 规则 | 说明 |
|---|---|---|
| 1 | 定位容器 | 每份 HTML 取 3 个 `field--name-field-passage` div，按文档序 = P1/P2/P3（与 `Part n` 标题交叉校验，错位即报错） |
| 2 | 段落切分 | 容器内每个 `<p>` = 一段；**段内不二次切分**（对齐粒度=段落） |
| 3 | 剥标签 | 去 `<strong>/<em>/<a>` 等标签保留内文；**剔除空标签**（实测大量空 `<strong></strong>`）；HTML 实体解码（`&rsquo;` 等） |
| 4 | 文本规整 | 折叠连续空白/换行为单空格；统一弯引号→直引号可选（建议保留原样，翻译质量更好） |
| 5 | 过滤噪声 | 剔除空段、纯符号段；`field-passage-desc` 内容作为文章 `title`（不在正文里重复出现时） |
| 6 | 范围护栏 | 每篇段数 5–20、词数 350–1100；越界进失败清单人工确认，不静默入库 |

**入库流程**（对齐幂等/续传/失败清单惯例）：

1. 遍历 `papers` where subject=reading → `assetsJson.entry` 定位 HTML 文件。
2. `upsert` 预置库 `past-paper` → 取 `libraryId`。
3. `articleId = "<examSetId>-r-t<testNo>-p<passageNo>"`；已存在**跳过**（断点续传，`--force` 可重导）。
4. `paragraphsJson = [{idx, en, zh:null, audio:null}]` 落库（本期 `zh` 先留空也支持 `--with-zh` 一步到位）。
5. LLM 逐段翻译（`src/lib/llm` provider）：逐条回填 `zh`；单段失败 `zh=null` 进失败清单，不阻塞整篇；支持 `--fill-zh` 只补漏。
6. `wordCount` 统计、`level` 默认 L3、`sourceRefJson = {examSetId, examId, paperTitle: papers.title, passageNo}`。
7. 跑 `reading-check` 校验：段数>0、zh 覆盖率、articleId 血缘与 papers 对应关系。

**完成判据**：两份现有真题（a-2025jan / gt-vol1）共 **6 篇**齐套入库；`zh` 覆盖 100% 或失败清单为空；重跑脚本零新增。

## 阶段 P3：后端 API（0.5–1 天）

**产出**：App Router route handlers（Next.js 16，注意先读 `node_modules/next/dist/docs/` 的现行约定）。

| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/reading` | GET | 库列表 + 各库文章（含进度快照聚合：lastParagraph/status/readSec） |
| `/api/reading/[articleId]` | GET | 单篇全文（paragraphsJson）+ 本人进度 + library/sourceRef |
| `/api/reading/[articleId]/progress` | POST | 上报 lastParagraph / readSec / status（upsert，`lastReadAt=now`） |
| `/api/reading/[articleId]/word-hits` | GET | 全文 tokenize → 命中 `words` 表词元集 + `inVocab` 标记 |
| `/api/reading/[articleId]/vocab` | POST | 加生词本（upsert words + 固定 `vocabulary` custom 词书 relation） |
| `/api/words/lookup` | GET | 词卡四要素（音标/释义/构词/读音路径，全出自 `words.contentJson`） |

要点：进度上报做**节流合并**（播放/滚动结束时批量上报）；`word-hits` 结果可按 `articleId+updatedAt` 做内存缓存。

## 阶段 P4：前端（1.5–2 天）

**产出**：两个页面 + 词卡组件，交互口径以原型 `docs/阅读学习原型.html` 为准。

1. **`/reading` 列表页**（学习中心导航「阅读学习」）：
   - 「继续学习」分区：`status=IN_PROGRESS` 的文章卡片（读到第 N/M 段 + 进度条），按 `lastReadAt` 降序；空态提示。
   - 「文章列表」分区：库 chips（本期仅 `past-paper` 一个库，样式按多库预留）+ 文章卡片（出处徽标/级别/话题/进度）。
   - 数据源：`GET /api/reading`。
2. **`/reading/[articleId]` 阅读器**：
   - 段落卡：段序号 + 纯文本正文 + 段末「译」按钮（对照显示 `zh`，`zh=null` 的段落按钮禁用态）。
   - 波浪线：`word-hits` 命中词渲染；点词弹 `words/lookup` 词卡（音标/释义/构词/🔊读音，本期可用的存量单词音频）；「加入生词本」。
   - 进度：滚动定位当前段 → 离开/切段时 POST progress；续读时滚动到 `lastParagraph`。
   - **播放控件整体不渲染**（本期 `audio` 恒 null，按显隐规范隐藏）。
3. 导航接入：学习中心顶部导航加「阅读学习」（背单词右侧）。

**完成判据**：从列表点开 → 阅读 → 点「译」→ 查词 → 加生词本 → 返回后「继续学习」出现该篇且定位正确。

## 阶段 P5：联测验收（0.5 天）

按设计文档 §8 验收清单逐条打勾（audio 恒 null、RESTRICT 删库、幂等重导、打卡计入 `study_activities`），并补两项专项：

- 清洗质量抽查：随机 2 篇逐段目检（无残留标签/实体/空段），中英段数一致。
- LLM 段译抽检 20%：长度比异常段人工复核。

## 排期总览与依赖

```
P1 建表(0.5d) ──► P2 清洗导入(1–1.5d) ──► P3 后端(0.5–1d) ──► P4 前端(1.5–2d) ──► P5 验收(0.5d)
                                        └─ P3 可与 P2 的 --with-zh 并行
合计 ≈ 4–5.5 天；本期不含 reading-tts（音频后置期）
```

- **硬依赖**：P2 依赖 P1 建表；P4 依赖 P3 API；P2 的 LLM 翻译依赖 `src/lib/llm` 配置可用。
- **风险**：① GT 卷（gt-vol1）结构若与 A 类不一致，清洗规则第 1 条的交叉校验会拦截，需人工确认映射；② 空段/残段比例高时第 6 条护栏会拦下大量段——按「失败清单 + 人工确认」处理，不放宽护栏。
- **扩展位**：后续 web/manual 源导入、新建库、reading-tts 音频，均在表结构上零迁移接入。
